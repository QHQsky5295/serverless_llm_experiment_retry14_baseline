## 阶段解释与剩余问题

平均进入原生引擎之前的时间为 2.101355 秒，占平均 TTFT 约 86.365%；
393 个请求在进入引擎前已超过临时 TTFT 阈值。
原生入口、原生排队、prefill 平均分别为 0.101220、0.016472、0.214057 秒。
控制路径等待仍是当前应优先解释的部分，不能因此把所有等待归因于一个 RPC。

1,815 条业务窗口控制采样中，734 条 queue>0，706 条队列为正且未占满
所记录 ready capacity；这是离散控制观测，不是连续 GPU 空闲证明。
规划共 2,026 条记录：2 条初始化、2,024 条 owned execution epoch，全部完成。
owned worker CPU 合计 1,123.445121 秒；新鲜源观测为 4,482 次请求、
4,165 次采集、16,595 次 RPC、317 次 join、418 次陈旧拒绝。
61 个成功请求记录 64 次源重试（最大 2 次）。这些次数不单独证明机制因果。

判断：**单轮完整观测支持继续保留该候选，但尚未达到系统目标。**
平均/P95/P99 TTFT、TPOT 和 E2E 均观察到下降；物理 GPU 占用只下降
约 0.065%，不能声称已证明有意义的资源节约或统计优越性。
与更早投稿 Prime 的同口径比较、数值正确性、共同 warm/Resident 参考仍缺失。
不通过重复同一候选寻找更好数字，不因优于上一慢版本而关闭旧系统差距。

下一步先封存并备份本轮，再利用已保存逐请求阶段与源观测证据，核查剩余
控制路径等待；结合已有修改历史及原始论文/官方代码，形成一个可证伪的新假设。
当前报告未选择另一个优化，不立即再跑 GPU 或进行容量/SLO 调参。
