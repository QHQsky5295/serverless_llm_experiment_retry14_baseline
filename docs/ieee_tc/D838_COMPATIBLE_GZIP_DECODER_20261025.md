# D838：固定归档下的兼容单线程解码候选

2026-10-25执行前登记，基点D837/6b0c7715，生产仍D831/D836。
未达标主线仍3B W2联合92.075%（差117条），D711数值身份未知。

## 可证伪假设

D837实际profile显示标准解包inflate约85–91ms、CRC约29–30ms；直接
`r|gz`反而增加工作，已拒绝。新假设不是流水化或增加并发，而是以兼容
单线程gzip解码器减少**相同压缩字节到相同文件内容**的CPU计算。
这不改变IEEE公式、缓存/驱逐/预算/路由、线上字节、远端准备或生成合同，
不移除owner校验，不是论文新算法。若组件更慢或内容不一致则不采用。

历史检索未发现此前isal/igzip候选；D825已去除流上重复SHA，本轮不重复此项。
D628移锁、D595/D598并行ACK、D822共享压力、D834成员复用均不重开。

## 官方依据与适用边界

- [python-isal v1.8.0说明](https://raw.githubusercontent.com/pycompression/python-isal/v1.8.0/README.rst)
  列出gzip兼容接口及差异；本次只读解码，不使用其不同压缩级别。
- [固定版igzip源码](https://raw.githubusercontent.com/pycompression/python-isal/v1.8.0/src/isal/igzip.py)
  `IGzipFile`保留gzip文件接口，内部读器使用C实现；不使用`igzip_threaded`。
- [官方测试](https://raw.githubusercontent.com/pycompression/python-isal/v1.8.0/tests/test_igzip.py)
  包括截断和多压缩级别读入；这些不是本机已通过测试，需实际核查。
- D837已核查ServerlessLLM的多层加载与vLLM原生LoRA加载路径。其特定布局、
  pinned-memory设计不是该解压热点的直接替代，本轮不改制品格式或复制工件。

## 最小验证与停止范围

复用D837组件，只将两种tar模式替换为标准gzip和固定isal解码；tar结构、
逐文件限制、预分配、最终owner完整SHA及发布流程相同。固定ABBAAB六次，
保留全量wall/thread-CPU/profile，不做CI或推算完整SLO。相同finance_lora
归档读取一次，来源由D837决定而不是按本候选速度选择。仅一个临时物化目录。

额外检查解码器对完全读取的gzip截断、CRC和长度错误均拒绝；原始请求路径
的归档SHA和目的文件SHA仍是独立强校验。组件通过不等于完整请求路径合格。
若有明确收益，下一步仅小幅接入及针对HTTP/取消/发布的现有测试，再完整
W2回放；不追加多轮组件搜索或冗余短性能回放。

依赖仅以官方PyPI固定wheel安装到本次raw/dependency，保存下载SHA和安装
文件清单；不更新现有vLLM环境、不改其他系统。CPU2/3/26/27、3/4GiB、
swap0，无GPU；复用150GiB磁盘与147项保护规则。无新权重、负载、远端服务
改动、请求打包或人工延迟。所有正式未完成范围保留。
