## 与论文的时间定义一致

- 服务初值由原生边界计算：`D=acquired-admitted`、
  `T=first-acquired`、`O=last-first`，单位转换为毫秒。
- 准备初值 `d` 由实际加载起点到 GPU 可执行事件计算，不用服务 `D` 替代。
  Remote 包含已经开始加载后的传输、本地校验/物化和后续等待；不扣除该路径
  中属于请求的真实开销。
- 已受保护的 GPU 命中按定义 `D=0`，不伪造一个“零时间加载”样本。
- 预热保留在原始记录、生命周期和失败记录中，不加入代表性初值。
- 保留 observed native-HOST 等待；不根据期望层级顺序修饰数据。

既有 `FrozenServiceProfiles`、`FrozenPreparationProfiles` 重新核算均值。
导出不接受缺失类别、不完整 pending 关闭、不同时间域、错误原生 token 数、
超过 1 ms 的重算误差，或重复/不属于该请求的传输。文件内容身份、原生来源
表示和真实 footprint 保留；加载参数仍是已经冻结的开发配置。

## 身份与复用合同

实测子进程配置逐字段匹配 D88 开发合同，除既有允许排除的设备放置 ID 外，
不删除字段。上下文绑定三项 SHA：合格原生环境回执、资源包络、输入/交付合同。
具体结构和规范化 JSON 哈希规则保存在每模型 manifest 中。资源合同包含
72/80 GiB 推理服务、swap、CPU、外部监控保护规则，以及 2/4 GiB、swap=0
的已发布远程交付服务、1000 Mb/s 实际链路条件。后续运行仍必须验证实际条件，
不能仅复制哈希就宣称合格。

原生初始化快照只提供几何布局；不把旧运行的 readiness、owner、epoch、地址
或空闲容量复制成新副本的实时状态。导出的参数是开发初始化，不是已冻结的
生产最优点或共同 SLO。

文件：`paper_results/ieee_tc/p2_backend/d89_{3b,7b}_initialization/`，每组包含
`service.json`、`preparation.json` 和来源/均值/绑定 manifest。
数据总量约 5.6 MiB，不复制原始大日志或工件池。脚本复用
`scripts/ieee_tc_preflight.py` 的类别检查、原生加载计时和已有 profile 读取器。

## 接入检查与保留的失败

在实际 `ExperimentStack` 和 `ScenarioRunner` 构造中读取两组 profile，核对
完整 500 个静态身份、W=5 秒的需求/完成观测绑定和 movement limit=3。没有
启动引擎、发送请求或发出远端 HTTP；仅创建并清理本次空工作目录。
同一检查确认 Full 未完成资格时仍拒绝执行，未增加绕过开关。

第一版离线驱动脚本误读清单字段 `size`（实际为 `size_bytes`），在构造前失败。
第二版把已解析的子进程配置作为新的父级请求配置，令
`requested_enforce_eager` 从原始 `auto` 变成 `False`，严格身份检查正确拒绝。
第三版直接使用 D88 原始记录中的 `requested_model_config`，再经同一实际
子进程解析入口，两个模型均通过。未修改生产解析逻辑、放松匹配或重跑测量；
三版脚本及失败日志全部保留。

六项新增导出测试通过；包括相关启动、服务/准备计量和基本检查在内的
430 项回归通过（36.065 秒）。147 项旧投稿保护内容无变化。
