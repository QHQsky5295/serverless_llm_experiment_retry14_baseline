## 已有证据与本次问题

D564 已完成原生 batch8 全 prefill、4/4 混合及完整 context1024 KV 分配；
释放原始 FP32 表示 5,469,372,416 字节，基座/准备后表示内容和指针未变。
req_00015/index131 的原生分数直接解释了 D562 的首次输出差异：batch8 中
11029 与1024并列13.703125，原生 argmax 选择1024；batch2选择11029。
这解释了决策，不自动证明高精度正确性或所有 adapter 的数值身份。

D564 混合调度另有 req_00104/ecommerce_lora_0045 在 index54 首次从10894
变为5936，共192/256个位置不同。原探针未采集该位置分数，原因仍未知。
不得把其归为已证明的舍入噪声、错误绑定或通过重复直到相同来消除。

## 唯一新增诊断

复用同一 D445 的8条既有760-input/256-output请求、D560源视图及D561推导
容量8。扩展原容量入口的显式 completed_phases_v2 模式，从已完成 D564 两个
调度中提取全部首次分歧；源SHA、输入、adapter、完整计数、比较标志与两个
phase缺一不可。只核查既有 req_00015/index131 和 req_00104/index54：

1. 每条目标分别用两个并发副本执行完整256输出，作为本次 batch2 参照。
2. 同一8条输入执行全prefill及4decode+4prefill，两目标同时观察。
3. 保留各case全部输出，并按原生位置保存完整32000分数、SHA、真实前缀、
   adapter/segment、原生选择和原候选分数；预期共8份向量。
4. 最后仍验证8条完整1024上下文的KV分配与排空，不上调容量。

观察器先调用并原样返回原生贪心 Tensor；不强制旧token，不改变 logits、
历史、EOS、权重、目标长度或在线后端。前缀若提前变化则如实记录，不能称为
相同前缀对照。不新增误差容忍阈值，不以“差得小”自动判正确。无新的输出
差异时同样保留；有新的差异不串行无限扩展本诊断。
