本轮在线重新核查：

- [vLLM官方CPU路径分析](https://vllm.ai/blog/2024-09-05-perf-update)：
  同时区分管理计算量、同步与GIL竞争；其API/engine进程隔离不等于将大量
  共享锁事务交给线程。不借用其硬件上的性能改善比例。
- [Python 3.12 asyncio](https://docs.python.org/3.12/library/asyncio-dev.html#running-blocking-code)：
  executor可避免在事件循环线程直接执行阻塞函数，但不能消除同步函数本身
  的工作或应用锁依赖。此资料只支撑边界解释，不证明本机退化原因。
- [vLLM 0.30 LoRA owner](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/worker_manager.py)：
  原生adapter集合、加载和激活仍由后端管理；本回退不变更后端所有权或公式。

压力、D834成员复用、D737/D744规划时机、D844第二遍stat局部FFI、D838–D840
