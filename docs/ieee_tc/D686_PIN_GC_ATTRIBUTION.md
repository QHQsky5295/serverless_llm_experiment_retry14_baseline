# D686：批量查询候选长停顿的有界归因

2026-10-18。承接D685唯一实际微测，不是新性能候选或系统成绩。
D685语义一致，19/20次稍快，但候选出现137.280433ms未知停顿；不能按均值
或中位数单独决定采用。D682仍为完整3B成绩，92.350%联合SLO，尚未达标。

本次只做一个额外原因观测，随后结束这一查询接口局部方向或根据直接证据
提出新的系统级假设。沿用D685共享库、同tiny fixture、四种图检查、原20组
顺序；不重编译、不加载backbone、不重新生成工件/负载、不访问远端。
这是观察器改变后的归因执行，不替代D685、不合并计算“更好成绩”。

## 假设、反例与原始依据

候选新增每view含Tensor tuple，可能改变Python分配和GC触发位置；当前只
是源码提出的假设。用[Python3.12 gc.callbacks](https://docs.python.org/3.12/library/gc.html#gc.callbacks)
记录实际回收开始/结束、generation、线程CPU时间、回收对象数，与完整
清点的时间窗关联。保留正常回收，不disable、collect、freeze或调阈值。
不枚举全堆对象；观察器自身仍可能改变分配计数和触发位置，必须披露。

同时核对本机实际和[官方vLLM0.30 GC实现](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/utils/gc_utils.py)：
EngineCore初始化已有freeze_gc_heap，shutdown已有unfreeze；它冻结启动期
静态对象，不等于禁止所有后续回收。小型资格没有EngineCore，不能把其
回收状态直接等同正式服务，不能重复移植已有冻结逻辑。
[官方EngineCore](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/v1/engine/core.py)
与本地文件分别记录SHA；不假设在线tag与本机字节完全相同。

## 判定与停止规则

- 只运行一次观察器版本；所有点保留，不删除长点、不追加到停顿重现为止。
- 观测到停顿时，按同一monotonic时间域计算与GC区间的交叠；不把全程GC
  累计从某个请求或微测中减掉。没有相关事件就不能认定GC是原因。
- 即使新运行中的停顿与GC重合，也不追溯证明D685旧137ms的确切原因。
- 完整图等价性和9种真实pin状态继续核查；无backbone数值正确性结论。
- 不用本次受观察器影响的均值替代D685、不生成CI、不启动前缀或4000回放。
- 不足以支持局部方案时保留不采用，返回3B完整路径；不得扩大成持续GC调参。

## 实际结果与裁决

61项CPU测试通过；唯一实际CUDA诊断的9种pin状态和4种完整图结果一致。
观察器记录431次GC，逐代数量与Python统计增量完全相符，事件不重叠、未截断。
回收开关、阈值`[700,10,10]`和已冻结对象数375前后相同；没有改回收策略。
本微测并非“完全未冻结”，但没有执行真实EngineCore启动后的大堆冻结。

| 本次带观察器调用 | 原生逐view查询 | 批量候选 |
|---|---:|---:|
| 调用数 | 20 | 20 |
| 平均完整清点（ms） | 9.026847 | 13.590629 |
| 中位（ms） | 9.055990 | 8.597515 |
| 最大值（ms） | 9.367870 | 109.359295 |

19/20个配对中候选较快，配对比中位0.954922；这些是同一微测中的调用，
不是独立系统实验。候选index1的109.359295ms窗口包含generation2回收
100.545234ms及generation0回收0.032600ms，合计交叠100.577834ms，
占该调用91.9701%。因此本次长停顿具有直接回收时间证据，而不是纯网络、
GPU等待或仅凭“可能GC”的猜测。不能据此宣称新增tuple是全部原因；没有
反事实分配实验，观察器也可能改变触发位置。D685旧137ms原因仍不追溯确定。

所有点保留，未扣回收时间构造“调整后性能”，未与D685合并选择更好一轮。
**裁决：结束pin-query接口局部方向，候选不进入生产，不启动该候选的前缀
或完整回放。** 正式vLLM已有启动堆冻结，不能据此另加全局GC禁用或把已有
机制当作新贡献。下一步回到现有D684所定位的完整控制路径，优先核对新鲜
清点的对象表示/遍历工作与实际消费；需新的可证伪证据才注册新候选，不能
以epoch/TTL缓存跳过真实tensor、storage、pinning或隐藏字段检查。

D682完整3B依旧为4000个原生合同完成、458224 tokens、联合3694/4000
（92.350%）、15896.253912 GPU-s。独立数值证明仍未知，`n_correct=null`，
不能把此次tiny状态正确性当作全模型证明或宣称G1/G2达成。
