## 发现的分析范围缺口

原D818远端阶段诊断只筛选实际dispatch tier为Remote的请求。D995只对已经
到达的需求提前准备文件，实际dispatch时可能已经是NVMe；因此旧条件队列
变小不证明远端传输变少，更不能证明到达时已命中。已有宏观TTFT/TPOT和
物理GPU积分不受此条件筛选影响：arrival-to-admission本来包含早期等待。

另外，原CSV writer通过第一行推断列名；合法的零Remote条件队列会触发
IndexError。零队列不是零远端开销，也不应导致完整结果无法诊断。

## 现有分析器的局部扩展

仅编辑`audit_d703_3b_full.py`中的离线D818路径及现有分析测试模块：

1. 保留全部物理传输表与旧的dispatch-Remote分解；显式schema允许空表，
   不填假请求，也不忽略空表原因。CSV写入仍先定LF字节、再计算SHA。
2. 新增arrival_preparation.csv，依据实际请求回执记录准备状态、实际
   dispatch tier、观察/准入时刻、文件等待、transfer ID和下载所有权。
3. 同时核对请求/adapter/clock、真实到达与准入边界，以及完整共享传输回执。
   下载创建者不能使用早于自身开始的传输；订阅者允许加入先前已开始的下载。
4. 同一物理transfer不能有两个创建者声称拥有IO；订阅者记录关联但不再
   累计一份物理字节。全部实际线上字节仍以global transfers为准。
5. 缺少早期回执标为unrecorded，不自动填成无准备；没有任何早期记录时，
   其拥有字节汇总为null，而不是断言实际远端字节为0。
6. 文件等待位于原arrival-to-admission之内，不再加到E2E，不扣除任何时间。
   native_presence_hint只表示跳过可选提前准备，不能作为GPU-ready证据。

这不是更换主评价指标，也不是从历史结果减去时间构造“优化后数据”。旧封存
结果和分析产物不改；新增输出必须使用未存在的目录。
