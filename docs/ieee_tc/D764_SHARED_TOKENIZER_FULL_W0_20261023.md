## 2. 观察与解释

1. D764完整通过4000请求计量；与D760的2522响应／1478失败相比，原来中后段
   长时间无响应没有在本轮重现。D760原始失败及重新核验结果永久保留。
2. D760内存峰值79027851264 B、high事件9124680、swap约2 GiB；D764峰值
   51459633152 B，high与swap均0。这支持必要的共同分词器适配消除了本轮
   观察到的重复构造压力，不证明它单独解释了D760的每一种异常。
3. 改动基于D761原生CPU对象保留证据、D762共同分词器逐字节合同和原生编码
   检查、D763真实GPU受影响路径。RR、autoscaler、原生loader、缓存所有权、
   target=8、min=1/max=4、1800秒保护等不变；没有追加基线性能参数搜索。
4. 普通编译缓存具有不同执行历史，因此D760/D764不是隔离单一变量的因果
   性能对照。失败运行的条件延迟不能直接与完整4000请求延迟作公平优劣结论。
5. 首500请求联合89.4%，其后七段为98.0、98.0、99.4、99.0、99.6、100、
   98.4%。53个联合违约在首段，38个在后续。此为事后描述切片，主结果仍为
   全4000请求，不删除启动请求、不用分段制造独立重复。
