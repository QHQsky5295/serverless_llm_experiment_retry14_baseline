# D98：以副本身份确认选中来源，避免无关引用导致重选

日期：2026-09-28。基于 `00568948795e223b6b2367e364c66fd19e2863f4`；
属于 Prime IEEE Full 开发修正，不是新的评价协议或已通过的性能实验。

## 问题、历史证据与可证伪假设

D97 完整回放只有 1609/4000 成功；成功子集平均用户 TTFT 为 1084.328 秒，
其中 dispatch/admission 为 1081.057 秒。927 条成功请求累计保留 11727 次
来源重选。以上只能定位主要等待阶段，不能证明全部延迟都由同一种冲突造成。

D96 已有原生 owner CPU 反例：32 次请求引用同一份实际不变的对象/slot，
只有第一条被接受，其他 31 条被全局 epoch 拒绝。D96 只合并并发读取，
没有修改该 guard；D97 只处理隔离后的实际释放与恢复，亦未修改它。

本轮假设：把任意引用计数变化都视为选中副本失效，制造了无需重选的冲突。
若改为同一串行 owner 内验证具体副本身份，并重新检查实时资源，应该允许
多个请求引用未变化的副本，同时仍拒绝真正的驱逐、替换、层级变化和失效 owner。
是否改善完整负载的成功率与等待时间，仍须实际回放验证。

## 参考实现与第一性原则

核查 [vLLM 0.30.0 LoRA worker manager](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/worker_manager.py)：
原生 LRU 路径复用已加载 adapter，只有缺失或 load-inplace 时加载，且管理操作
在单线程 engine core 中执行。引用增加并不等价于权重副本被替换；本次保留其
缓存、驱逐、加载和原生线程模型，不替换底层后端。

[Linux sequence-counter 文档](https://docs.kernel.org/locking/seqlock.html)
说明版本变化会触发读重试，也说明高写入活动可能导致大量重试。这是通用并发
背景，不是 Linux 文档对本机瓶颈的证明，也没有向 Python 引入内核锁。
本次明确区分**对象身份、层级有效性、引用生命周期、当前容量**四件事。

## 实现合同

| 保持的论文语义 | 本轮实现 |
|---|---|
| 选中副本的最快有效层级；GPU 必须实际可执行 | HOST 使用已有 CPU 对象 incarnation；GPU 使用独立发布 incarnation。移除立即撤回，重新确认产生新身份 |
| 同一快照路由，执行时重新检查 | 路由证据携带选中 source_id；只在同一原生 owner 内比较身份/实际 tier 后获取引用 |
| 预算与物理可行性 | 仍检查当前 pin、slot、HOST 预算、实际引用；不复用旧容量决策 |
| planner/admission 的独立职责 | 全局 epoch、联合替换计划、E(t)、KV 与字节保护均不改；不把副本 ID 当容量许可 |
| 取消、未知结果、资源释放 | 原有 lease、幂等回执、终态确认、隔离与物理 release 规则不变 |

只在已确认 native GPU/HOST 的选中来源路径使用副本身份。Full 的此路径缺少身份
会明确拒绝，不能静默降级；既有 epoch-only API 调用仍保留严格 epoch 检查。
文件/Remote 来源、主动准备计划、排序公式、服务估计、生成、配置、工件、负载、
超时和远端交付条件不变。无新增周期、TTL、重试上限、sleep 或经验阈值。

## 当前 CPU 证据

实际执行同一原生 owner 代码，缓存对象/原生 slot 采用现有 CPU fixture；
不执行 CUDA，不代表 GPU 并发吞吐或真实性能：

| 层级 | 确认方式 | 同一观测下接受/32 | 额外加载 | 最终残留引用 |
|---|---|---:|---:|---:|
| GPU | 原全局 epoch | 1 | 0 | 0 |
| GPU | 选中副本身份＋实时检查 | 32 | 0 | 0 |
| HOST | 原全局 epoch | 1 | 0 | 0 |
| HOST | 选中副本身份＋实时检查 | 32 | 0 | 0 |

四组对象身份及 slot 图均保持不变。该对照只证明无关引用冲突可以消除，
不证明 D97 的全部排队来自这个问题。

第一轮新增 8 项测试在实现前 7 项因不存在 source_id 报错、1 项通过；
这是缺失合同的红测试，不冒称 7 个历史运行故障。实现后 8 项通过。
实际 router→selected-source admission→native owner 集成及相关检查 78 项通过
（1.630 秒）；最终模型/相关回归 1168 项通过（53.771 秒），另在合格系统解释器
完成 47 项 OS 保护检查（0.132 秒），共 1215 项不同检查。覆盖预算不足、失效
owner、幂等及 HOST 重载；未改变原生运行环境或为过测试降低保护条件。
旧“仅人工增加 epoch 应重选”测试改为真正 deactivate/reconfirm 后重选，同时
新增真实 acquire/release 不应重选的对照，保留取消和 pending-intent 收尾验证。

初始两次短测试保留工具输出摘要，未声称存在逐字原始日志；后续集成、反例对照
与回归保存完整日志。原始目录 `results/ieee_tc/p2_backend_qualification/d98_20260928/`。

汇总时首次因 results 符号链接的物理路径不位于 V2 worktree 下而失败，发生在
六个空 CPU scope 已清理之后；失败日志保留。修正汇总脚本的路径表示后成功，
未重跑实验或修改数据。最终结构化结果含 15 项来源 SHA，147 项旧结果保护检查

## 下一步与边界

local-only 审查已检查副本移除先于 slot 回收、相同 ID/slot 重载、引用幂等、
实时预算和取消保留边界；没有调用子代理。完成来源/旧结果校验和代码备份后，回到既定
canonical 3B Full4000 W0；只改变已验证代码和新的独立输出/缓存路径。
