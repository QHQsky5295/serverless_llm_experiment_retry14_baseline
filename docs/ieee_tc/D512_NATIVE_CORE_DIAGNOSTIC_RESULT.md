## 解释与下一步

当前状态查询和准备路径仍有可观测的、主要消耗线程 CPU 的开销，因此不能
把所有解码差距都归给 GPU 算力。该证据支持进一步检查新鲜物理视图构造的
重复工作，但尚未证明这些操作能解释全部885.733 GPU-s生产差额，更没有
证明删除它们可以同比获得收益。模型 step 仍占大部分正常请求解码窗。

下一项只允许基于当前源码和历史反例选择一个语义保持的优化：检查一次
权威观察内的重复张量/存储身份遍历，或将只需身份的消费者与实际容量证明
区分；先证明不牺牲新鲜 pinned/alias/容量/admission 状态，再最小验证和
一次完整回放。不使用跨调用 TTL/epoch 身份缓存，不重复 D352/D355/D474
已完成改动，不盲目扩大并发或改变 cooldown。若没有安全可证的重复工作，
转向原生 step 的迭代组成，不机械追加 snapshot 补丁。

原始来源和官方代码依据见 D512_CURRENT_NATIVE_CORE_DIAGNOSTIC.md。
