## 4. 历史否定证据与下一单一假设

- D606/D609已减少文件观测组织的冗余，不重新开展同一库存优化。
- D627定位发布内SHA，但D628移锁在D629完整W2未获支持，D631已撤回。
  本轮只有包络时间，没有足够新证据重开同一移锁候选。
- D595将不同owner的start/finish并行发送；D598中联合达成下降0.50个百分点、
  U增加3.55%，没有整体收益。不能以本轮仍观察到确认耗时就重复该改动。
- D680同owner HOST→GPU租约交接、D747/D751原生描述优化保留；不回到已关闭
  的元数据局部扫描、GC或pin方向。

下一待论证的唯一方向：**将同一物理文件域的实时传输压力作为权威共享观测，
在原生准入的实际检查点读取，避免每次IO必须经过所有推理core的双向确认**。
这不同于并行化同一批RPC；需要先证明其一致性、生命周期和IEEE公式映射，
目前尚未实现，不能声称已减少开销。压力必须在IO前可见，实际writer/清理结束
后才能撤销；新owner加入、旧owner退休、取消和未知终态都不能伪造零压力。
不得删除Eq.(8)/(9)的压力项、缓存陈旧值或把文件物化移到计量外。

官方依据只用于设计，不代替性能证据：

- [vLLM 0.30共享内存广播源码](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/distributed/device_communicators/shm_broadcast.py)
  使用共享缓冲区与显式可见性/通知，说明本机进程间通信不必始终复制完整消息；
  不直接复制其同步假设，也不把广播队列等同于本项目的权威压力状态。
- [vLLM 0.30多进程执行器](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/v1/executor/multiproc_executor.py)
  展示共享队列与worker生命周期管理；其TP collective和本项目三个独立副本
  不同，不能直接套用。
- [Python 3.12共享内存文档](https://docs.python.org/3.12/library/multiprocessing.shared_memory.html)
  明确跨进程close/unlink生命周期；共享内存本身不自动保证多字段原子性或
  正确同步。候选必须使用真实进程间同步/所有权，不依靠普通Python赋值猜测。
- [ServerlessLLM原论文入口](https://www.usenix.org/conference/osdi24/presentation/fu)
  强调加载路径与层级局部性；这里只支持分离本地加载与远端传输的问题组织，
  不把本轮全部成本归给网络，也不宣称同一实现已被该论文验证。

先完成一个有界、无需GPU的实际跨进程一致性/失效验证；若语义无法保持，
拒绝该方向并返回其他已测瓶颈。通过后才考虑必要的原生路径资格和新版本完整
回放，不再重复无问题指向的smoke，也不提前承诺最终胜出。
