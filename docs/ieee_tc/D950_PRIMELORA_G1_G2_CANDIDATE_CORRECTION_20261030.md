# D950：PrimeLoRA 7B/3B 主线候选的 G1/G2 分离裁决

## 为什么需要分离候选

冻结协议不是把“最低 GPU-s”和“最低尾延迟”合并成一个未经定义的分数。G1 与 G2 是两个不同的研究目标：G1 在共同服务可行性成立后优先比较物理生命周期 GPU-s；G2 在共同资源预算下比较扩容/churn 尾延迟。因此同一个模型可以有不同的 G1 候选和 G2 候选，不能因为 TTFT 更低就称其为 G1 最优。

## 当前观测裁决

### 7B

- **G1 候选：D931**：物理 GPU-s 11,716.0641，平均 TTFT 1,215.95 ms，P95 TTFT 2,997.74 ms，联合 SLO 98.1%。
- D947 初始 NVMe preload 候选的 TTFT 为 1,144.78/2,464.45 ms、SLO 98.5%，但物理 GPU-s 为 13,296.43；在 G1 口径下不能取代 D931。
- D947 可保留为 G2/延迟敏感性候选，不改写为 G1 资源胜者。

### 3B

- **G1 候选：D935**：物理 GPU-s 11,936.5504，平均 TTFT 803.77 ms，P95 TTFT 2,302.04 ms，联合 SLO 99.875%。
- **G2 候选：D937**：物理 GPU-s 11,941.4112，平均 TTFT 775.71 ms，P95 TTFT 2,204.69 ms，联合 SLO 99.975%。它的尾延迟和 SLO 略优，但 GPU-s 比 D935 高约 0.041%，因此不能称为 G1 资源改进。
- D935 与 D937 的差异很小；在外部 baseline 和共同预算比较之前，不从这个差异推导算法性结论。

## 证据边界

D931、D935、D937 均完成 4,000/4,000 原生请求合同并捕获原生 token IDs，但没有独立的全负载数值 LoRA oracle，`n_correct` 继续保持 unknown。该状态不能被成功请求数、输出长度匹配或 token digest 自动升级。

因此，本文件只选择后续实验的分析候选，不宣布 PrimeLoRA 已完成 G1/G2，也不要求为同一执行键重复运行。下一步应先完成统一 baseline 的请求级与物理资源证据，再针对真实差距提出新的 PrimeLoRA 优化假设。
