# D296：独立运行实例的退出依赖与生命周期 GPU 占用

2026-10-07。先登记假设，再实施候选；下方追加验证结果，尚无新的性能改善
结果。D295 三组数值诊断完成后返回本项，仍是7B主线，
不是3B、基线或额外消融任务。遵守源计划及冻结指标V1；达标前不画图。

## 1. 实测问题与可证伪假设

D293 完成100条开发请求后，物理GPU时间仍增加85.545933848 GPU-s。
最后请求终态为同一单调时钟805821.437170008；四张卡释放如下：

| GPU index | 释放时刻 | 终态后仍持有（秒） |
|---|---:|---:|
| 0 | 805831.023290198 | 9.586120190 |
| 1 | 805838.839926862 | 17.402756854 |
| 2 | 805846.658058565 | 25.220888557 |
| 3 | 805854.773338255 | 33.336168247 |

来源为D293 `launch.launch/physical_allocations/*.jsonl`及
`physical_deployment/request_terminals.jsonl`，不是逻辑实例删除时间。
当前`ScenarioRunner._shutdown_instance_pool`在共同准备任务结束后仍逐个
`await _cleanup_removed_slot`；后者等本实例真实退出才返回。因而晚处理的
独立实例会在无工作时等待前一实例退出。历史时间阶梯与这一实现相符，
但不能把85.55全部归为可避免开销，也不能由静态源码推导实际改善值。

假设：共同准备/激活任务已结束时，同时发起互不依赖的真实runtime退出，
可以减少串行依赖产生的持卡等待；不改变业务内路由、扩缩容决策或任何
请求时延定义。测量仍到实际物理release，不能提前记账或事后减去清理时间。

## 2. 历史约束和原始资料

- D94/提交`df09f25`：draining不是空闲，释放确认之前保留成员和设备占用。
- D97/提交`d6733aa`：先加入既有quarantine退出，避免同时关闭同一engine。
- 提交`0e2adf9`：RPC响应不等于原生退出；关闭连接、进程终态、原生worker
  和GPU census共同限定release。此次不删改这些步骤或已有超时。
- [vLLM0.30进程管理源码](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/v1/utils.py)
  的`shutdown`先向全部所属进程发起退出，再在共同期限内等待。这提供
  “发起与等待分开”的参考，不证明Prime共享任务也可无条件并行。
- [Python3.12异步任务文档](https://docs.python.org/3.12/library/asyncio-task.html)
  说明gather的异常/取消行为。需要完整加入所有已发起的退出，再报告失败，
  不能因一个实例失败而留下无主退出任务。

官方资料于2026-10-07核查；实际使用已安装vLLM0.30，不升级环境。

## 3. 最小实施与验收边界

1. 先用既有测试/InstancePool构造CPU反例：首实例等待退出时，另一独立
   实例应已开始；取消、异常均不能使未确认GPU成为可用资源。
2. 保留前置顺序：quarantine、initial activation、residency、准备计划、
   shared movement owner、pending scale-up全部settle后，才处理实例。
3. 同一engine的逻辑别名不得并发重复shutdown；不同真实owner可以并行。
   所有待退成员先退出路由，成功确认后才移除，失败成员及错误证据保留。
4. 通过有关生命周期回归后，复用D293的100请求开发输入/配置与真实远端
   合同，只登记新输出目录；观察物理release间隔、完整GPU-s及TTFT/TPOT。
   对初始化page cache等不同条件如实标注，不以总量单次差异夸大因果。
5. 最小验证最多两轮；没有新证据不反复试到胜出。合理后返回完整7B回放
   和共同SLO/预算标定，不把退出优化或100请求完成当作G1/G2达标。

这是资源生命周期实现优化，不是新的论文算法贡献；IEEE九式、生成协议、
95%联合SLO、60秒准备、资源保护、远端交付与失败分母均保持不变。

## 4. 候选实现和 CPU 验证（性能运行之前）

既有`_shutdown_instance_pool`按engine对象身份分组，共享engine别名串行，
独立组同时退出；所有已经开始的退出任务settle之后才报告异常/取消。
未改`_cleanup_removed_slot`、真实GPU回收判据、超时或论文公式。四项反例
在原实现因独立退出尚未开始而失败；改后通过，覆盖独立退出、共享别名、
