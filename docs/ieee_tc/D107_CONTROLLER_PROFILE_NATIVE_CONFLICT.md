## 首个服务异常与后续症状

native `ieee_prepare_host` 在 `residency_manager.py:2505` 抛出
`replacement epoch source identity or GPU confirmation changed`，随后经过 RPC
成为主控制器的 RuntimeError；回放连接中断，外层记录
`protocol_or_launcher_error` / `external replay failed`。后者不是首个原因。

当前 guard 检查冻结来源与**全部当前 CPU 来源交集**中的名称/路径，并核查
每个已占用 GPU slot 的确认状态。它不是 D105 的父进程“当前准备目标路径”检查。
日志尚未保存失败瞬间的具体冲突项，因此不能仅凭异常断言是哪条来源，或断言
已经证明“合法的另一层副本”而非身份/确认损坏。

失败计划 `437932963ab644518524d54c838f4f27` 保存 19 条 attempt：11 次延后、
6 次完成、2 次 `native_outcome_unresolved`，后两者 adapter 整数 ID 为 441461、
497501。这不意味着发生两次相同异常；未决结果不能伪报完成。关闭计划获得确认，
全部物理 GPU 释放，文件引用根目录删除，cleanup/measurement errors 为空。

采样器外层退出码为 0，只证明采样器成功收尾；不能替代服务的失败状态。
远端两服务、独立远端监控及本地辅助组均在核查身份后停止，未停止无关任务。
