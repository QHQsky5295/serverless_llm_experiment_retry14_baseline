## 可支持的论文判断

1. 在 W0/W1/W2 三个已测 3B 工作负载上，PrimeLoRA 达到了共同联合时延
   参考点，并比已达标的 vLLM、ServerlessLLM 观测使用更少的物理
   GPU-s；这支持“质量约束下的资源效率”方向，但仍受数值正确性资格和
   单轮观测边界限制。
2. PrimeLoRA 的 P95 TTFT 没有在这些场景中优于 vLLM 或 ServerlessLLM。
   论文应把这一结果写成资源—尾延迟取舍，而不是宣称所有指标第一。
3. HydraServe/Loquetier/dLoRA 的低 GPU-s 行不能参与达标资源比较，因为其
   联合服务要求未满足或有效响应集合严重受限；删除这些行会掩盖对照边界，
   所以保留并明确标注。
4. 这组结果不证明 PrimeLoRA 在所有配置或所有模型上全局最优，也不能用
   CE、低成本或平均延迟抵消尾延迟和联合达标率的差异。

## 下一步边界

3B Full 主线的三种 workload 已有同版本观测；后续新增 GPU 运行应只服务于
已登记的机制/敏感性缺口（例如 S2/S3、S4–S9 或有限预算点），不能重复
同一 Full 键寻找更有利数字。7B 受控 S2/S3 仍是当前机制证据主线；若没有
同 cache 位置/同候选的合法控制条件，则保留其证据缺口，不把自然 LastKnown
或 route-shadow 结果改写为完全因果实验。
