## 假设、历史与依据

D187定位了当前控制器中的同步准备快照；D188组件对照仅证明重复静态
计算可以移出该路径，未证明端到端收益。本轮直接实现这一候选，不重复
微测/诊断回放，不叠加新优化。保留D153一次完整实时文件扫描、D159单个
规划worker和D163不可变计划查询，不重复此前已处理的瓶颈。

可证伪假设：从已冻结文件清单复用内容摘要和目标描述，减少每次准备的
同步工作；完整W0中的用户TTFT/TPOT或GPU占用若未改善，则不宣称净收益。

重新核查[vLLM官方CPU开销分析](https://vllm.ai/blog/2024-09-05-perf-update)、
[Python asyncio同步工作说明](https://docs.python.org/3.12/library/asyncio-dev.html#running-blocking-code)
以及[vLLM 0.30.0 core client](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/v1/engine/core_client.py)。
这些支持检查对象构造/同步边界，不提供本机加速倍率或论文机制证明。

## 唯一改动及不变项

- 内容索引配置时构造不可变描述；文件名、大小、SHA与逻辑字节完全来自
  既有索引，嵌套映射和文件对脱离输入，没有未来请求信息。
- 同内容重复配置不替换已冻结对象，不同内容仍拒绝。旧可变导出API保留。
- owner仅保存一个目标模板，按内容/subset、实际根目录和每次实测分配粒度
  绑定；条件变化重新构造。占用仍为逐文件上取整，不使用平均大小或模型名。
- 可变输入每次验证；不通过对象地址、TTL或verified标志跳过输入检查。
- 每个快照仍进行新鲜完整库存、二次stat、确认来源检查和预算/预留计算。
  返回的目标及来源均为私有副本；静态描述不携带tier、ready、epoch或余量。
- 九个IEEE公式、选择、执行重检查、取消、源所有权、profile、容量、SLO、
  超时、工件、负载及远端交付不改变。没有第二worker或按测试点调参。

构造时间和元数据内存仍由实际服务进程承担，不移到免费外置预处理。
部署及实际持卡计量按原生命周期执行；CPU-only阶段不虚构GPU占用。
