# HydraServe：非项目集群的隔离适配决定

2026-10-12，用户确认：现有 k3s 集群不是为本项目部署，授权采用合适的适配方式。
此决定补充完整 PLAN，不改变 PrimeLoRA 优化优先级，也不允许基线性能调参。

- 不再以“等待确认集群归属”为下一步；不重复询问已经回答的问题。
- 不复用或改动该集群的现有服务、权限、令牌、网络、GPU 分配及数据。
- 优先资格验证本项目独立、可回退的部署：使用已存在的 rootless Podman
  能力，在项目自己的资源域中核查 GPU 容器、必要编排与 worker 限制。
  独立部署是否满足 HydraServe 原生行为仍待验证，不声称已经可用。
- 若 rootless 路径不支持所需 GPU/编排语义，先分析官方部署依赖和可行的
  项目独占替代；不得静默借用陌生集群、修改主机全局服务或绕过权限。
- 保留官方修改版 vLLM、pipeline、启动重叠与 consolidation；允许必要
  平台/模型/API/计量适配，不以裸 vLLM 替代后冒称 HydraServe。
- 在实际 worker 的内存/CPU/GPU 归属、LoRA 传播和回收资格通过前，
  不启动重型回放。无性能实验与安装/构建并行。

继续遵守 D447 及 baseline 仓库三个既有审计文档：原生源码已保留；
LoRA 层身份与共享结构尚需真实执行资格。此决定解除旧的归属不明问题，
不是授予现有集群管理员权限，也不是 HydraServe 复现完成证据。
