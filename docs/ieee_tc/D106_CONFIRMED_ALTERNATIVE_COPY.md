# D106：相同工件的不同已确认副本与准备目标有效期

2026-09-28。证据基础 `2b16bb25c449be081673b1e187a53eb7755b2c8b`；
此前生产版本 `00f0f8da3061f89cfbb857200da1ac9b20fd1560`。
本轮是 Prime IEEE Full 的正确性修正，不是新性能结果或正式 SLO 资格。

## 观察与可证伪假设

D105 在 59 条到达、58 条提交后，以 `native HOST target source identity changed`
提前中断。检查把 adapter 名称差异和物理路径差异合并为一个错误；失败时的确切
快照未保存，不能追认当次一定是同内容副本，也不能确认是哪一个 adapter。

本轮 CPU 反例使用实际分层文件管理器发布同一工件的 HOST/NVMe 副本，核对两份
内容 SHA，再由实际 native owner 从 HOST 注册加载。准备任务仍携带 NVMe 路径。
在 native HOST-only 和 GPU-ready 两种状态下，原实现都到达 D105 的同一检查并
抛出原异常。缓存对象和模型是既有 CPU fixture，不执行 CUDA、不生成实验权重。

因此证据支持一个有限结论：**不同路径不必然是错误工件；它也可能表示旧准备
目标的物理来源已被合法请求改变。**这证明代码存在该缺陷路径，不补造 D105
缺失的失败现场，也不证明此前 30 条超时或全部排队时间来自此问题。

## 历史、参考实现与论文边界

D98 已区分 native 对象 incarnation 和无关引用 epoch，但没有改变主动准备的
路径绑定。D104 处理的是冻结来源集合不再覆盖当前缓存，同样没有处理相同工件
从另一合法文件副本加载的情况。

核查 [vLLM 0.30.0 LoRA worker manager](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/worker_manager.py)：
原生 LRU 按整数 adapter ID 查找已加载对象；缺失或显式 load-inplace 才重新加载，
否则复用对象并激活。加载路径、对象身份和层级就绪状态不是同一概念。此源码
只支持设计语义分析，不是本机性能证据，也不授权仅凭名称放行另一份权重。

本次保留 IEEE 九个公式、冻结需求/收益、逐层预算、admission 和物理容量。
不改 profile、后端版本、生成契约、trace、deadline、资源配置或远端交付。
不更换预测器，不加入 TTL、轮询周期、重试次数、sleep 或经验阈值。

## 实现合同

| 论文规范语义 | 当前实现与边界 |
|---|---|
| 准备目标绑定已观测的具体来源及成本 | 来源路径发生已验证变化时结束旧目标，不在旧收益上重定价或驱逐 |
| 同一工件不能只由目录名判断 | 核对 native owner/clock、完整覆盖、整数 ID、名称、rank、source ID；实际 file owner 确认两路径及同一冻结内容 SHA |
| 已加载对象不被重命名成另一副本 | 保持其 native 路径/身份和 slot 不变，不重载、不伪报准备成功 |
| 计划不是跨多次 RPC 的原子预留 | staging、native HOST 队列、native GPU action 三个已有检查边界使用同一失效判定 |
| 物理操作必须收尾 | 复用既有 superseded 终态：等待已提交工作，关闭旧计划，释放已确认引用 |
| 稳态反映当前状态 | 只有旧计划完整收尾后，后续正常周期重新观测和规划；不重试旧 objective |
| 受控 handoff 保留目标约束 | 失效向上传播，不在同一受控调用中偷偷选择另一组目标 |
| 错误或证据不全不能当作正常变化 | 外来 owner/clock、错误名称/rank/SHA、未确认 GPU、文件被修改、缺失来源等仍拒绝 |

本修正需要**两份当前已确认文件发布记录**。原文件已被撤回而 native 对象仍存活
等情况不由本次证据覆盖，不凭路径相似或仅相同 adapter 名称推断内容一致。
该负面判定不授予新 lease、加载或预算；不是把任何异常吞掉后重试的兜底。

## 正确性验证表

| 检验 | 结果 |
|---|---|
| 原代码，同内容不同路径 | 1 个测试的 HOST/GPU 两个子例均复现原 ValueError |
| 修改后，两种 native 状态 | 旧队列任务明确失效；native 绑定不变，无额外加载、无遗留引用 |
| 正常请求在 staging 前或 HOST 队列前加载另一副本 | 实际 owner/队列/稳态回收通过；旧计划关闭，后续新计划完成 |
| 正常请求已准备目标、旧 native GPU action 才执行 | 不以旧路径继续；没有第二次加载或驱逐；新周期复用实际状态 |
| handoff 与异常收尾 | 不静默重规划；既有关闭未确认、兄弟任务失败检查继续通过 |
