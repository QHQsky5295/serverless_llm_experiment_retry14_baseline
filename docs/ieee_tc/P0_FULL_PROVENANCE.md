## 配置与状态的区别

- 显式 scale cooldown 都是 2 秒。
- 在线得到的 effective scale-down cooldown/min-idle 分别为
  55.240950 与 55.634687 秒；这是观察到的运行差异，不是已经证明的延迟差异原因。
- HOST cache 当时可用量不同；不据此推断物理内存压力的因果作用。
- 主表有 TOTAL_REQUESTS 环境覆盖记录，消融无此记录，但两者均执行 4,000 请求。
- 两个 manifest 记录的主项目 commit 为 `cd0a527da86e62eb4c410d5058fcb8994ab3c284`
  与 `57f9855a23a91a623d760cd325666932dee299f0`；提交间仅实验日志变化。
  manifest 并不是完整环境冻结，不能由此断言所有未记录状态都一致。
- generation seed 在两份 metadata 中均为 null；旧生成协议不等于 TC 的固定输出合同。
- 输出 token 总量分别为 407,351 与 405,927；即使输入相同，实际完成工作量也
  不完全相同，不能把所有 E2E/吞吐/成本差异仅归因于调度或运行波动。

## 对新实验的约束

同一主结果的表、图、正文必须引用同一个 canonical run-set；同条件 Full
可直接复用主比较，不额外挑一次更好的 Full。独立配对或受控 activation
实验可以使用另一 run-set，但必须明确条件和身份。

旧结果保留为 R2 历史证据；这次 P0 审计本身不需要重跑模型。
3B 主表的来源另有独立记录，本核查不伪造不存在的 3B 对应旧消融运行。
