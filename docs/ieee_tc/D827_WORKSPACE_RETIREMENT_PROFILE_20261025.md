## 已知事实与本轮问题

D826的498条唯一关联Remote请求中，文件发布至客户端结束均值116.368ms；
之后线程返回41.914ms、压力finish241.867ms、加载交接195.436ms。第一个
包络包含workspace清理、owner锁等待及调度，不是已测的unlink或库存扫描
CPU时间。本轮仅验证**无竞争时实际workspace退役工作是否足够大，值得成为
一个独立优化候选**；不能用包络减去组件时间推断在线锁等待。

代码显示transfer_workspace退出时在owner锁内移除私有目录、退役预留记录、
重新观察文件库存并通知实际容量变化。安全职责包括不提前释放真实物理占用、
处理失败保留路径、避免inode复用绑定旧预留；不能直接删除此路径或异步
丢给不计费的后台任务。D606已消除库存路径表示往返，D609/D610已合并extent
settlement扫描；不重新包装为新方案。D628移SHA锁、D595并行压力RPC与D822
共享压力已有完整负面结果；本轮不恢复它们。

## 方法、复用与边界

使用system-profile外置包装法，复用D605受限入口、D627 MeasuredLock、
D825现有文件成员流与真实LocalSourceReferences。两种组件条件各三次：
空库存和D557已关闭只读元数据库存（只改变遍历基数，不模拟在线3B驻留）。
使用既有32MiB单个工件，最多一份临时payload；不生成权重/负载或复制整池。
workspace内另预留并写入既有adapter_config原字节作为待清理的小文件，
走原prepare_transfer/cleanup路径，但明确**不代表真实gzip、网络或大归档
unlink耗时**。本轮问题是清理中的库存/状态工作，不测交付吞吐。

外置计时区分workspace退出wall/thread-CPU、owner最外层持锁/无竞争获取、
嵌套inventory与rmtree。嵌套项不重复加到总时延。验证最终内容、已发布目标
保持、临时路径及归档inode预留退役、原文件/只读库存/147保护集合不变。
组件没有在线竞争；不能用其毫秒值改写D826服务时间或计算反事实SLO。
若工作很小，关闭“单独优化清理就能解决剩余差距”的假设，返回主交接问题，
不启动无依据GPU回放。若明确存在较大冗余，再登记一个语义等价候选。

CPU2/3/26/27、3/4GiB、swap0、GPU不可见，复用磁盘/内存保护；所有原始
组件值保留，不算运行间CI。无在线插桩，无生产修改，无图表。

## 实际结果：组件已完成，尚不支持独立清理优化

唯一组件进程退出0，原scope已inactive且路径消失。六次调用全部满足目标
内容确认、workspace删除、归档inode预留退役、已发布目标保留；生产文件、
源工件和既有只读元数据库存均未变。下面是全部原始调用，单位ms；嵌套列
已经包含在总wall中，不能再次相加。

|---|---:|---:|---:|---:|---:|---:|
| 无 | 0 | 0.380875 | 0.380215 | 0.368002 | 0.124299 | 0.121191 |
| 无 | 1 | 0.431171 | 0.429346 | 0.404573 | 0.112942 | 0.105732 |

1. 删除这个1050B占位归档及私有目录仅约0.10–0.12ms；不能据此认定真实
   大归档的unlink同样快，但没有证据支持将本次rmtree单独当作主要瓶颈。
2. 带库存时耗时主要位于真实容量清点；其中一次为140.266ms，不删除、
   不截尾、不用其余两次冒称全部稳定在10ms。对应线程CPU140.240ms、
   无竞争锁获取0.001727ms，说明本次长点不是组件内owner锁竞争，具体
   函数内原因未测。不得称其必然是冷缓存、GC或线上锁等待。
3. D686历史曾直接观测到另一组件的GC长停顿，但不能追溯证明本次原因。
   本轮不重开已经关闭的GC/pin/元数据表示调参，不disable/collect/freeze，
   不反复跑到长点消失。D606、D609/D610的库存改进也已在当前实现中。
4. D827是7B单个工件和独立只读元数据库存，D826是3B在线混合路径；两者
   工作集、竞争和观察器不同。不能以116.368ms减去10ms或140ms恢复在线
   lock wait，更不能用组件值重算反事实TTFT、联合SLO或物理GPU时间。

**裁决：本轮不选“单独删除/异步清理”生产候选，不启动额外GPU回放。**
这个局部问题到此结束；全量容量观察和inode退役职责保持。回到D826已有
完整路径的发布后交接与控制任务竞争，下一候选必须先说明与D595/D598、
D628/D629、D687/D688、D822负面结果的实质区别。若现有日志缺少在线
等待边界，先承认证据不足，不把任一包络直接归因于可删工作。

内存峰值343113728B，high/max/OOM/swap均0，CUDA未初始化，无远端访问。
这不是新的完整性能成绩；当前完整3B W2仍为D826的90.25%联合SLO，
未到95%，D711独立数值身份限制仍保留。
