# D1106：vLLM 7B W2 正式留出运行结果与审计结论

D1106 是与 D1103 ServerlessLLM 7B W2 完全同 trace、同 500-adapter view、同
`fixed_length_greedy_v1` 生成合同的 vLLM 对照运行。它使用 vLLM 0.10.2，四个
TP=1 数据并行副本，GPU 0--3；LoRA 制品由远端预发布交付缓存严格 materialize
到本地后再启动推理。请求期间未进行打包，也没有把预发布 materialize 时间放入
请求级 E2E。

## 完整性与合同审计

所有硬门槛通过：

- 预期、完成和成功记录均为 4,000；HTTP 200 为 4,000，失败、空成功和重试均为 0。
- request ID、adapter ID、arrival time 和 source expected-output map 与 shared trace
  逐条一致；request-map SHA-256 与 D1103 同为
  `548deafa98b85b6e9cd0c2dd55b2a1ef5a2e09a204df541f2cfcc0e96a198b83`。
- 4,000/4,000 记录的 generation contract 和 `output_contract_match` 均正确；
  `completion_tokens == requested_completion_tokens` 为 4,000/4,000。
- 所有记录的 `guard_prompt_tokens <= 759`，`guard_max_tokens == requested_completion_tokens`；
  vLLM usage 的 prompt token 比 guard 值统一多 1，这是 vLLM usage/BOS 计数约定，
  不改变 prompt guard 或输入身份。
- 所有记录均使用 `vllm_token_ids`；native token-id invalid count 为 0，native
  token-id count 与 SSE integer token count 一致。文本重新分词只保留作 audit，
  不作为主 token 数。
- `E2E = dispatch/admission wait + service E2E` 的逐请求误差不超过 1 ms；按
  service E2E、service TTFT 和 native output token count 重算 TPOT，逐请求误差
  不超过 1 ms。
- 语义正确率字段本次不由 vLLM endpoint 提供，不能据此声称数值正确率；本结果
  仅用于同合同的服务性能、SLO 和资源对照。
