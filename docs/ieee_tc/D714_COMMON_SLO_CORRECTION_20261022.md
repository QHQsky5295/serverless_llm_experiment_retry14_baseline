# D714：D703 的联合 SLO 字段误标，离线修正而非重跑

2026-10-22，在 D713 回放期间核对统计路径发现。此记录是评价实现纠错，
不修改冻结 V1/V2、D648 阈值、运行配置、原始结果或历史审计 JSON。

## 已确认的错误与影响

`scripts/run_all_experiments.py` 的 `slo_attainment` 只统计成功请求中
`overall_ttft_ms <= ttft_slo_ms` 的比例；D703 的在线配置是 5000 ms。
它没有检查 TPOT，没有应用 D648 按原生 prompt 长度分组的共同阈值，
一般情况下分母也不是全部 offered 请求。

`scripts/ieee_tc/audit_d703_3b_full.py` 原审计直接将这个字段复制为
`joint_slo_fraction_observed`，并乘 4000 得到 `joint_slo_count_observed`。
因此旧回执的 3995/4000=99.875% 是开发用 TTFT 单项观测，**不是共同联合
SLO**。D703 结果说明、D711/D712 及历史 EXECUTION_STATUS 中沿用它的
“共同/联合达标”和与 D682 的 SLO 提升解释暂时撤回，以新离线重算为准。
物理 GPU 时间、请求完成事实与原始延迟并不因这个标签错误自动失效。

旧审计保留：`paper_results/ieee_tc/p2_backend/d703_3b_full_w0_d701profile/audit.json`，
SHA `c6e6d56ff39734eb87ced593bf1858db6c781f467c771a359794e0e1a0e0e997`。
不覆盖它，不伪装原审计一直正确，不用已见到的结果放宽评价阈值。
