# D731：同一控制轮共享一次文件层观察

2026-10-22。开发候选，CPU 路径资格完成；尚无新完整 GPU 性能结果。
主线仍为 3B W0 的共同 SLO 与物理 GPU 时间，不改 IEEE 九式、V1/单轮 V2。

## 现有证据和可证伪假设

D729 全 4000 请求的联合达成率 90.725%，距 95% 仍缺 171 条。
D730 分解显示，本机提交至服务接收均值 149.718 ms、P95 928.956 ms；
这不是远端 LoRA 链路时间，也不能直接归因某个 Python 函数。
本次复用同一已关闭运行的日志，没有新增诊断回放。

| 已记录项目 | 数量 |
|---|---:|
| 控制事件 | 1910 |
| 稳态驻留规划 | 3699 |
| 这些规划所在的控制间隔 | 1570 |
| 每间隔 1 / 2 / 3 / 4 个不同目标副本 | 436 / 440 / 393 / 301 |
| completed / superseded / cancelled | 2398 / 1298 / 3 |

同一间隔内规划开始时间的最大跨度为 0.513365 ms。历史没有显式 round ID，
上述分组按控制时间线恢复，并由无 await 的调度循环核对，不伪称已有原生
round 字段。3699 次规划与代码路径支持重复观察同一个共享文件 owner；
不能证明这些不同时刻的观察值完全相同，更不能换算为 CPU 时间或 SLO 收益。

可证伪假设：每轮为同一个共享 HOST/NVMe 文件域获取一个完整物理观察，
再供本轮各副本规划使用，能减少控制事件循环上的同步工作。可能的代价是
部分副本看到更早的文件状态、发生更多 supersession；完整回放同时检验。
不能把 3699→1570 的观察次数投影称为 57.56% 端到端加速。

## 与历史、原始资料及论文的关系

- 保留 D93 来源/预算同 epoch、D153 同次库存、D457/D606 新鲜路径表示。
- D329 说明 owner/epoch 不能替代物理分配清点；本次没有 TTL、跨轮动态缓存，
  每次共享观察仍调用原完整双重 stat、来源验证和预算构造。
- 纯 DP 已在独立进程，不重复外移；不再次优化已关闭的 HOST pin/GC/startup
  小方向，不将锁内调用简单转线程后继续阻塞其他同步 caller。
- [Python 3.12 asyncio 文档](https://docs.python.org/3.12/library/asyncio-dev.html#running-blocking-code)
  说明同线程同步工作会推迟其他协程；
  [vLLM 官方性能分析](https://vllm.ai/blog/2024-09-05-perf-update)
  提供测量 CPU 管理开销和组件异步性的依据。只借鉴方法，不借用其加速比例。

显式候选开关为 `ieee_residency_file_observation: control_round_v1`，未指定时
保持原 per-replica 行为。它是执行设计身份，不是根据 workload/胜负调节的阈值。
新完整运行沿用 D729 其余计算配置，只改这一项和独立输出/缓存路径。

1. 先确定本轮没有在途计划的不同 engine；空轮不读文件、不重复建立任务。
2. ready 副本在原 activation 路径中已完成 HOST/file-domain 绑定；在发布池
   成员前的原顺序不变。对共享文件 owner 同步观察一次，记录 owner、epoch、
   观察时间、耗时、round ID 与参与副本数。
3. 每副本仍独立获取完整、新鲜的原生 GPU/HOST 图、保护集和真实几何。
   不等待最慢副本形成全局屏障，不将新 native 报告当成全局原子快照。
4. 各副本需求窗口、成本序列和原 IEEE 选择器保持原入口；序列化后视图脱离
   可变字典。读取时序不同，live 选中集合可能变化，不声称动态决策恒等。
5. 计划只是观察，不持有源引用、不预留字节。原执行入口的来源引用、实际
   预算、冲突/supersession、取消与回收检查保持不变。共享观察不授予四份预算。
6. 下一控制轮重新观察；handoff 不使用该共享轮视图。取消某副本不取消兄弟
   副本，也没有新增脱离生命周期管理的后台任务。

## 资格、限制与安全记录

针对性证据共 32 项：首次已完成的新候选 5 项和原 owner/混合执行 22 项直接
复用，随后补实际 remote→HOST→GPU 路径 1 项及调度/取消/退出 4 项。
使用真实文件 owner/选择器/执行器与受控 native 测试对象；不是新原生 GPU
数值验证或性能实验。既有 native/CPU-process 资格不重复。

首次选择整个 launcher 文件过宽，未修改的后端导入子进程触发辅助组
memory.high：峰值 3467382784 B、high 38282、max/OOM/swap 0。按确切身份
停止整组，保留 incomplete 日志和强制收尾回执，不写成全部 204 项通过。
第一次收窄入口因工作目录错误没有收集到测试；保留失败记录。修正工作目录
后只运行上述尚未完成的 5 项，全部通过，峰值 633344000 B，无内存事件。
这些是检查组织问题，不删失败，也不改变生产算法来绕过测试。

下一项 D732 是一个普通完整 4000-request W0，不额外新增短前缀；复用
D725 的同计算配置 profile、D648 共同 SLO、D80 只读交付和既有资源隔离。
仍需至少 3800 条联合达标，真实 GPU-s 按物理生命周期累计。检查共享轮观察
次数/耗时、规划失效、接收/slot 等待与 TPOT，不只展示局部扫描减少。
独立数值 adapter 正确性仍未知，不能据此把 `n_correct` 从 null 改为 4000。
未达标不进入该候选 W1/W2；所有历史结果和其余完整实验范围保留。
