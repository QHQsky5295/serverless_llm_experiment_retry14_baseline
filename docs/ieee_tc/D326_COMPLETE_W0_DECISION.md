三次全部达到 released，均无 quarantine、未决请求或状态查询错误。前两次
证明不再要求副本碰巧空闲才开始回收；没有中断已接纳请求。三次启动撤销时
均无正在等待的 source collection，该分支在本轮未触发，不声称实际测过其收益。

物理已释放至下一次占用的间隔总量115.647→169.279 GPU-s，增加53.631；
各卡首次到末次占用的包络总量同时增加16.912 GPU-s，所以净变化为
`16.912 - 53.631 = -36.719 GPU-s`。这是实际区间恒等式，不是无缩容反事实。

互斥窗口的变化为：到达前+0.062348、到达窗口−43.973653、drain+3.839393、
cleanup+3.352853 GPU-s，合计−36.719060。不能把 release 提前到逻辑撤销时刻。

控制记录中，D323 为两次实际回收及一次等待空闲；D326 为三次实际回收。
D326 第二次撤销后约4.187秒又出现扩容决定，随后一次请求扩容时无空闲设备，
之后再次实际扩容。这提示容量变化与准备期间的服务质量值得检查，但不是
已经证明的尾延迟成因，也不能据此加入防振荡定时补丁或修改冻结控制阈值。

## 5. 决定与下一主线

1. D325 的论文生命周期语义得到真实触发支持，保留其正确性实现；这不代表
   接受“性能已达标”，也不按单次胜负撤回合法完成已决定缩容的语义。
2. 这次假设的性能部分仅获混合证据：微小资源下降、TTFT退化。不得追加同配置
   重复筛赢家，或用 CE、idle 折扣、放宽 SLO、去掉真实传输掩盖退化。
3. 下一项仍为7B：围绕缩容后可服务容量与后续 activation 期间的等待，核对现有
   控制/生命周期记录和实现是否一致，结合历史及官方实现提出一个可证伪候选。
   不再重复本次完整性审计、相同短前缀或输出长度标定；不堆叠未验证修改。
4. 数值资格、共同 warm/Resident、新指标下旧 Prime 对照仍未完成，不能把
   本轮暂定时间通过率称为最终验收。7B未闭口前不进入3B或 baseline。
5. 3B优化、Serverless优先的基线工作、M1/M2、核心消融与敏感性全部保留待做。
