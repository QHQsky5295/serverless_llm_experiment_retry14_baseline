## 3. 机制触发与解释边界

D330 的 publications=2931、seeded scopes=68507、hits=8408，机制确实触发。
这些是实际计数，不是避免的 RPC 数，也不转换为虚构的延迟/GPU-s 节省。
选中后的实时源核验、原子引用、GPU-copy 校验、HOST 失效和 budget 检查保留。

平均 admission 分解如下；前三项可相加，routing 包含在 runtime wait 内，
不能重复加到总量，分位数也不能相加。

| 区间 | D326 (ms) | D332 (ms) |
|---|---:|---:|
| 计划到达至入口放行 | 200.398 | 218.301 |
| dispatch window 等待 | 33.984 | 33.803 |

| 内含 routing | 151.842 | 71.717 |

TTFT 平均下降 87.544ms，其中 admission 下降 86.773ms，service 仅下降
0.771ms。因此观测支持当前路径的等待减少，不支持“原生推理本身显著变快”。
闭环路由、缓存和扩缩容轨迹同时变化；不能把这 87.544ms 全部作 D330 的
无噪声因果收益。入口迟到增加也保留，不从用户时间线中扣掉。

实际控制记录有 9 次新增 activation、6 次 drained retirement；D326 分别为
6 次实际新增、3 次回收。D332 持卡互斥窗口为到达前 36.609807、到达窗口
15301.141209、drain 5.638241、cleanup 39.098956 GPU-s，总和等于完整 U。
更频繁回收不自动证明收益，不能从逻辑撤销时刻提前停止计费。

## 5. 决定与下一主线

1. 保留该实现作为当前单一开发候选，接受“本轮观察到改善”，不宣布 G1/G2
   或旧系统新指标验收通过。不再为这个已触发的局部改动追加短前缀或重跑筛赢家。
2. 下一项仍是 7B。先复用现有记录核对入口迟到和 runtime 等待的边界、已有
   控制路径修改及同类官方实现，选择一个能降低端到端等待/持卡需求的可证伪
   原因。不要把整个 runtime wait 当成没有容量，不盲改并发、SLO 或 cooldown。
3. 两个已验证下载归档的回收已恢复有限磁盘余量；新重型任务前仍须实测门槛，
   不删除当前编译缓存、模型/工件、唯一结果，保持150/100GiB门槛。
4. 数值资格、共同 warm/Resident、旧 Prime 新指标对照保持开放；不重复已完成
   的 D295 数值三块来筛 exact。必须补齐真正缺失的验收证据才能结束本模型。
5. 7B→3B→Serverless优先的基线工作→M1/M2→消融/敏感性，顺序不变。
