# D1162：7B G2 预算工作点更正

日期：2026-11-09  
性质：对 D1161 的口径更正；不启动新运行，不修改 D1161 原始记录。

## 1. 更正内容

D1161 只引用了 D1115 的 max4 Full，因此误写为“7B 尚未形成 G2 预算工作点”。
该判断不完整。D1117 和 D1118 已经在同一三副本上限配置下完成 W1/W2，并且
分别满足共同联合服务要求和各自的 75% 预算：

| 场景 | 运行 | 联合 SLO | 生命周期 GPU-s | 预算 GPU-s | P95 TTFT (ms) |
|---|---|---:|---:|---:|---:|
| W1 | D1117 | 97.575% | 6545.885 | 6756.571 | 2469.504 |
| W2 | D1118 | 97.500% | 9873.292 | 12086.669 | 3053.004 |

两点均完成 4,000/4,000 请求，并且属于同一三副本上限配置；不能把 D1115/D1100
的 max4 Full 与 D1117/D1118 拼接成不存在的配置。

## 2. 正确的 G2 结论

7B 已经具有一个预算内的 PrimeLoRA W1/W2 工作点，因此可以报告：

- PrimeLoRA 在已登记的 W1/W2 工作负载上存在同时满足共同 SLO 和 75% 预算的
  实际工作点；
- D1117 相对 D1115 将 GPU-s 降低 13.91%，但 P95 TTFT 上升 5.93%，联合
  SLO 下降 0.975 个百分点；
- D1118 相对 max4 W2 工作点将 GPU 时间降低 6.11%，但 P95 TTFT 上升
  8.45%，联合 SLO 下降 0.55 个百分点；
- 因此，预算工作点支持“预算内服务可行性和资源—尾延迟取舍”，不支持所有
  指标同时改善。

与外部系统比较时，D1118 的 W2 表显示 vLLM P95 TTFT 更低但超出该预算，
HydraServe 虽处于预算内但联合 SLO 只有 66%。因此，在已测工作点中，PrimeLoRA
是同时满足预算和共同 SLO 的可行点；这仍不是对所有系统配置的全局最优证明。

## 3. 对 D1161 的处理

D1161 保留为当时基于 D1115 max4 表的阶段性记录；其“尚未形成 G2 工作点”
的结论由本更正和既有 [D1140 7B 主比较闭口记录](D1140_7B_PRIME_COMPARISON_CLOSURE_20261108.md)
替代。后续汇报和论文表格不得再使用 D1161 的该句结论。

当前 7B PrimeLoRA 自优化阶段已按 D1140 的边界闭口，后续重点转向已登记的
A2/A4 机制证据、剩余敏感性以及 3B 对应主比较；不重复 D1117/D1118 或重新
寻找同一预算工作点。
