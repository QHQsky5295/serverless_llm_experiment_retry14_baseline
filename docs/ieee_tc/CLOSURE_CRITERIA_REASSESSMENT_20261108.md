## 1. 最终建议

主叙事应为“在明确服务质量要求下的资源效率，以及预算约束下的服务能力”，
不回到 CE 第一，不要求所有裸延迟同时最低，也不把资源少但尾延迟高自动
称为全面胜出。最有说服力的是向外推进资源—质量可行边界，并用真实机制
回执解释推进原因。仅处在 Pareto 前沿不等于优于所有其他前沿点。

保留当前 G1/G2。用户建议的多维图是合理方向，但必须分清三个对象：

1. 请求级延迟阈值 theta：多快才算及时；所有系统相同。
2. 达成率要求 q：例如至少95%的请求同时达到 TTFT/TPOT 阈值。
3. 实测达成率 A：例如98.55%，由数据决定。

“A 都不低于95%”是相同最低服务合同，不是实际达成率相同。放宽 q
只改变某个实测点是否可行，不会让该点的 U 或 A 自动改变。不能复制同一
运行到70/80/90%三列并把不变资源画成已测得的三种在线资源配置。

## 3. 主评价及补充曲线的数学定义

所有点必须满足共同输入、工件、原生生成、初态、资源计量和已定义正确性
合同。未知正确性不变成已证实；当前原生合同观察与独立数值证明分别标注。
令 N 为4000，x为一个已经登记并实际执行的系统配置，w为场景：

\[
A_{s,x,w}=N^{-1}\sum_r z_r\mathbf1[TTFT_r\le\theta_r^T]
\mathbf1[TPOT_r\le\theta_r^P],\qquad
U_{s,x,w}=\sum_d\int a_d(t)\,dt.
\]

失败、单token处理、时间域、实际release仍遵循冻结 V1，不另造分母。

### G1：相同服务要求下的资源效率

\[
R_s^*(q,w)=\min_{x\in\mathcal X_s:\ C_{s,x,w}=1,\ A_{s,x,w}\ge q}
\frac{U_{s,x,w}}{N}.
\]

C表示完整正确/计量有效。此式是已测候选集合的描述性包络，不能叫理论
全局最优或未测配置的最小成本。空集写“未观测到可行点”，不写无穷值或
“该系统不可能达标”。目前主表仍使用每模型已冻结 resource_opt，不在各
场景事后换x。跨场景选择必须是同一个x满足全部规定场景，再按既定等权目标
比较；逐场景包络须另标设计空间分析，不能冒充一个跨场景策略。

主点 q=95% 不变；既定90/95/99%完整保留。用户提出的70/80%可作为低质量
探索性补充，不代替主点，也不选择只让 PrimeLoRA 获胜的阈值。
仅有一个工作点时如实画一个点/阶梯可行区，不插值虚构更少GPU的实测结果。

### G2：共同预算下的尾延迟；达成率作为独立质量结果

\[
Q_s^*(B,q,w)=\min_{x:\ C=1,\ U_{s,x,w}\le B,\ A_{s,x,w}\ge q}
Q_{.95}(TTFT_{s,x,w}).
\]

既定 B=0.75U_ref、q=95%、同一个跨W1/W2的 budget_latency_opt 不变。
共同预算指相同上限，不强制每个系统实际花费相等；保留 U/B。
达成率—预算的辅助包络为：

\[
A_s^*(B,w)=\max_{x:\ C=1,\ U_{s,x,w}\le B}A_{s,x,w}.
\]

A包络不强求先达到95%，因此可以展示低达成率基线；不能把最大A的x与
最小Q的另一个x拼成同一行。0.5/0.75/1预算敏感性已在计划内，优先复用
有效实测点。仅相同峰值4卡不等于相同实际 GPU-s，不据此称严格等资源。

### SLO严格程度曲线与辅助效率

\[
A_{s,x,w}(\lambda_T,\lambda_P)=N^{-1}\sum_r z_r
\mathbf1[TTFT_r\le\lambda_T\theta_r^T]
\mathbf1[TPOT_r\le\lambda_P\theta_r^P].
\]

这种曲线可以用原始日志离线计算，x和实际U均不变；这是评价敏感性，不是
把在线策略重新优化了一遍。具体完整扫描网格在运行分析前登记，不根据
曲线交点裁掉不利区域。q轴和lambda轴不能混称“不同SLO”。

N_good/U 可作为 good requests/GPU-second；它与 CE 不同，也不能替代
最低质量要求，否则可能奖励大量违约。全部已测基线仍在表中，不因低于
95%而删除或无限优化。测得的最佳点只在已测硬件、负载、实现范围内成立。

## 5. 适用于所有实验的闭口规则

分开记录“实验完成”和“贡献主张得到支持”，避免把否定结果变成无限重跑。
首次有效同键运行完成、资源释放、全量证据保存并解释后，该执行键封存；
不能因为未胜出反复运行或额外削弱对照。贡献主张是否成立单独判断。

| 实验问题 | 能支撑的闭口证据 | 不足时的有界下一步 |
|---|---|---|
| G1资源效率 | 同合同完整工作，满足共同q，已测资源点更优，原始质量完整披露 | 先核查已有资源/质量包络；仅有新瓶颈假设时登记新候选 |
| G2预算尾延迟 | 同预算/共同q，实际U合规，尾延迟优势；joint差另报 | 不拼接不同工作点；复用既定预算敏感性找真实边界 |
| readiness贡献 | 同驻留/admission的LastKnown差异、状态年龄与实际决策/服务结果 | shadow只证决策差，不生成反事实TTFT；无效果则收窄贡献 |
| handoff贡献 | 实际关键路径准备提前，且first-service/排队或资源结果可归因 | 完成既定受控同计划A2/A4；计划计数不能当物理收益 |
| hierarchy/HOST贡献 | 实际复用/物化/字节/准备时间变化，完整后续代价 | 未减少remote次数就不称减少下载，可报告本地加载收益 |
| admission贡献 | 相同候选下加载干扰下降，延期任务的后续代价全部计入 | 完成既定S3，不能只挑局部decode窗口 |
| 规模/强度/churn等 | 预定点完整，领先与失效边界都解释 | 不追加有利点替代失败点，不冒充大型集群 |
| CE/价格 | 全范围敏感性和原始资源质量一致可追溯 | 只离线分析，不用挑选价格替代G1/G2 |

不设无依据的“所有组件至少提升X%”。组件的合理收益由其可影响的关键
路径决定：例如理想两项独立准备从串行I+P变为并行max(I,P)，可隐藏量
至多min(I,P)；这是给定活动模型的上界，不是保证实际请求尾延迟降低多少。
若早期物理工作近乎不存在，就不能要求它必然产生很大的重叠收益，也不能
加sleep、额外清缓存或阻塞对照来制造。大幅效果也需验证是否由非目标因素
引起；细小单轮差值不写成稳健提升。
