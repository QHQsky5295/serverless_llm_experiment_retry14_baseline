## 保留的评价尺子

- 全部 4,000 请求正确完成，无隐藏 fallback、少生成或漏请求。
- TTFT 从计划到达至首个原生输出 token；TPOT 为首末原生 token 间隔除以 n−1；完成通知尾部不计入 TPOT。Type-1 分位数。单 token 的 TPOT 为 N/A。
- 所有系统共用模型/长度分组的 warm 阈值，5×TTFT、2×TPOT；联合达标至少 3,800/4,000。
- G1：上述可行性成立时最小化真实生命周期 GPU-s/正确请求。
- G2：上述可行性、U≤0.75 U_ref 及共同资源包络成立时比较 W1/W2 P95 TTFT，另报联合达标率差值。
- 不以单独 TPOT 的相对退化代替联合可行性判断，不以 CE 或单独 TTFT 宣告最终优胜。
- 内容/请求/adapter/lease 证据与原生计量仍须完整。遵循 V1：跨后端不强求逐 token 相同；数值可区分性限制和同后端变化保留审计。
- 远端使用统一已发布只读缓存；请求触发的传输/竞争/必要物化计入时延。离线打包不进入服务路径，也不事后从结果中扣除。

## 单轮规则（替代 V1 §8 的正式重复与统计推断）

1. 每个模型×场景×系统×冻结工作点执行键只需要一次性能运行。首次有效结果封存；失败、不完整、环境干扰及启动错误保留分类和原始证据。
2. 不输出运行间均值、t-CI、Holm 显著性或统计非劣结论。请求级分布仍可报告，但 4,000 请求不是 4,000 个独立运行。
3. 低优差值为 baseline−Prime；相对改善为 (baseline−Prime)/baseline。联合 SLO 差使用百分点。仅称“本次观测领先/不低于”，不称“显著、稳健、全局最优”。
4. 已有多个相同执行键不得按结果择优。它们保留原身份；需要主展示点时采用事先指定点或最早计量合格点，并公开其他记录。不同开发配置的选择保留候选表和选择依据。
5. 新优化须有机制假设和新版本；不通过无限重复相同配置、改变阈值或隐藏退化取得领先。对手获得合理的配置与错误修复机会。

## 参考标定与复用

- 已完成的 D394 三轮 warm 样本是一次共同阈值标定，不为取消 CI 而重新生成或删除。资格核验后独立冻结 SLO manifest；冻结 SLO 不需要等待 GPU 预算参考。
- V1 §7 的 Resident 参考从三次均值改为每模型/场景一个完整、预登记且合格的运行：U_ref=该轮 U，Q_ref=该轮 Type-1 P95。B=0.75 U_ref 不变。既有 D395/D396 存在计量/资源归属缺口，不能因完成了 4,000 请求直接用于预算。
- 不追改历史 `formal_run=false`、源 SHA 或配置。通过输入、计时、来源、资源和初态逐字段核验的历史单轮可封存为 `reused_development_observation`。这是固定已知回放下的描述性证据，不是独立留出评估。
- 封存记录分别给出：原始身份、协议/分析键、源 SHA、观测可行性、未覆盖场景、复用等级和限制。只有 W0 数据不能宣告完整 M1/M2 或配置跨场景最优。
- 原始未知正确性字段不原地补写；如可按现有证据导出新指标，在新分析产物中写明规则和证据。不能用 HTTP 200 或目标长度单独推定 adapter 正确。

## 顺序与范围影响

先保存 7B Prime 合格的可复用单轮点，随后恢复 7B baseline；Serverless 历史问题优先。对比后必要优化，之后推进 3B。核心消融、confirmed-state、first-service、带宽、churn、负载、规模、CE 等完整问题集保留，只去除正式重复。

本修订减少运行成本，但不能消除两轮审稿对可重复性与外推的疑问；微小差异只具有单轮描述意义。最终论文必须准确陈述这一证据范围。
