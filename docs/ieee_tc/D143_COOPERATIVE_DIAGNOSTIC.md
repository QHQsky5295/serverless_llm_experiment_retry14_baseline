# D143：持有 Python frame 引用的控制路径诊断

2026-10-01，开发诊断资格，不是服务策略优化或性能改善结果。

D142 已证明旧 C-watchdog 在本机 CPython 3.12.12 的导入过程中可能崩溃，
并已撤回。本次沿用其启用门槛与文件隔离，只用普通 Python 线程调用
`sys._current_frames()`，复制文件名、函数名、行号后释放 frame 引用。
不使用 C-watchdog、信号、ptrace，不捕获局部变量、请求内容或源码行。
该 API 返回的活动栈并非冻结的全进程状态，不能作无偏 CPU profile。
[Python 官方说明](https://docs.python.org/3.12/library/sys.html#sys._current_frames)。

每次采样完成后等待两秒，保存实际时间、预定时间、采样延后、实际间隔、
进程 CPU 累计/增量、此前已完成观测的线程 CPU 时间及当前 snapshot wall。
线程 CPU 计时只计该观测线程；进程 CPU 包含其他线程，二者不混称。
[time 计时接口](https://docs.python.org/3.12/library/time.html#time.thread_time)。
存在 GIL 饥饿时采样可能延后，不补造样本、不集中追赶。记录包含 idle 栈；
没有 C/CUDA 内部帧，最多每线程 100 帧，截断显式标记。

## 资格结果

| 检查 | 结果 | 解释边界 |
|---|---:|---|
| 相关 CPU 回归 | 337 / 337，78.572 s | 不是 GPU 性能重复 |
| 新观测测试 | 6 / 6 | 默认关闭、严格启用、异常退出留存、覆盖保护、引用释放、GIL 延迟 |
| 故意持 GIL 延迟 | 显式记录延后，仅一个实际样本 | 不补造等间隔样本 |
| 当前 native 环境，关闭观测 | 导入完成，进程返回 0 | 没有加载模型/执行回放 |
| 同 native 环境，开启观测 | 导入完成，进程返回 0 | 只证明导入兼容，不保证 GPU 回放成功 |
| 资源域 | CPU 2,3,26,27；high 3 GiB、max 4 GiB、swap 0 | 实际读回，结束后空域关闭 |

开关新身份为 `python_frames_v1`；旧 `1` 拒绝。正式运行、错误 cgroup、
未放行 receipt、非 prefix 等均拒绝。默认保持轻量导入，观测只在启动门槛
之后启用。每进程 PID/启动 ticks 独立文件，JSONL 完整行即时写出；异常退出
的最后半行须保留并标缺失，不当作完整记录。后台线程异常不得被解释为零开销。
同进程重复调用幂等；fork 继承状态不能冒充已启动的子进程观测。
