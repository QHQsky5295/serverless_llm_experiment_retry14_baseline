# D204：复用 D203 数据定位剩余违约与输出身份差异

## 范围与结论

本项为离线诊断，不是新增性能运行。D203 普通 7B Full 已封存并备份；
复用其 34,389,917-byte 请求投影、既有 timing CSV、D195 有界投影和 D196
阶段表，不重读或重新投影数百 MB 原始结果，不生成工件或负载。
IEEE 九个公式、冻结 V1、模型配置、远端协议和服务代码均未改变。
用户最新的一次性只读交付缓存授权已经由 D78/D80 完成；本项不重建缓存。

主要发现是：剩余违约并非只发生于初始冷启动，源准入后的准备阶段仍值得
调查；126 条输出 hash 差异没有被原生 adapter ID 不匹配解释，但数值原因
尚未确认。不能据此宣布正确性、正式 SLO、G1/G2 或旧 Prime 对照已通过。

## 3. 输出差异审计及其边界

所有 4000 条请求在两个版本保存的原生 adapter 整数 ID 都与同一逻辑 adapter
的现有确定性映射一致。重新核对输出 hash，差异 ID 集合与 D203 封存结果
完全一致：

| 逻辑工件类别 | 请求数 | hash 相同 | hash 不同 |
|---|---:|---:|---:|
| all | 4000 | 3874 | 126 |
| finance_lora | 103 | 92 | 11 |
| medical_lora | 66 | 64 | 2 |
| other_logical_adapters | 3831 | 3718 | 113 |

后者对应之前工件审计的零更新类别；因此非零 LoRA 的算术不是解释所有差异
的充分原因。这也不能证明零更新请求一定正确：意外应用别的槽位仍需排除。
逻辑 ID、来源引用与原生调用 ID 相符，只支持提交身份链，不能替代每次执行
实际使用的 token-to-slot 映射或独立数值资格。

只有 672 对请求的两版 selected source 都保留文件内容 SHA，均相同。
另 3328 对至少一侧使用原生张量副本身份，当前字段不含可比较的文件 SHA，
明确标 unavailable_native_source，不从名称填补。D166/D167 的 44 个槽位
快照和独立 checkpoint 对照仍有效，但不能扩充为 Full 每 token 的证明。
当前投影保存的是输出 hash，不是逐 token 序列；首个分歧位置和该位置 logits
不可由 hash 恢复，不能虚构差异位置或默认全为浮点舍入。

核查 [vLLM 0.30 官方复现性说明](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/docs/usage/reproducibility.md)：
默认不保证输出复现性，在线模式另有 batch-invariance 机制。
[对应版本文档](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/docs/features/batch_invariance.md)
列明 NVIDIA compute capability≥8.0 的支持范围并提示性能影响；本机 SM86
没有因此被硬件门槛直接排除，但不等于当前完整 Llama-2/LoRA 路径已获验证。
[LoRA kernel 配置源码](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/ops/triton_ops/utils.py)
确有 batch-invariant 分支，shrink 使用 split_k=1，并避开外部 tuned config。
本机对应 utils.py SHA 为 ba7110f5f52b6b5172aede8cb15da4fac93358a0d0c7c4004743ed5a1c979343。
这些是候选解释和诊断工具依据，不是本次126条差异的因果结论。本轮未打开
该开关，未更换正式后端合同，未以输出接近阈值替代身份检查。

## 4. 下一步与主线边界

下一项先审查当前原生 token-to-adapter/slot 映射的可观测边界，复用既有
22 请求、4 个内容类别和已通过的 checkpoint→slot 证据；明确如何区分
执行错配与调度相关数值差异后，才补最小诊断。不能重复 D63 那种正反例都
接受的宽松概率检查，也不以改 tolerance 通过验收。

性能侧保留一个待证伪问题：源准入后的按需准备是否主要在原生执行队列中
等待，而非实际读取/复制。当前阶段数据不足以回答；D176/D184/D202 已做的
事务、流水线和表示优化不重复实现，也不根据本表立即加并发或再跑 Full。
先收窄可观测边界，不同时堆叠新优化。

7B 正确性、共同 warm/Resident、新指标下旧 Prime 对照及 G1/G2 仍未验收。
3B 仍未验收，外部 baseline、M1/M2、A1–A5、S1–S13 继续保留并按主线顺序。
