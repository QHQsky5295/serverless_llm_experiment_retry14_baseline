# D541：修复大编号 pidfd 的生命周期退出计量

2026-10-15。这是由 D540 收尾失败触发的公共计量修复，不是性能优化或新的
GPU 实验。D540 原失败已先推送为 `31526e77835ec8e70e0096de21dbc3b9375bfc19`。
不改变 S-LoRA、PrimeLoRA 或其他系统的推理、路由、扩缩容、生成合同和评价阈值。

## 假设、历史与原始依据

D540 完整4000请求结束后，在 `PhysicalGPUAllocation.wait_workers` 的
`select.select` 调用出现描述符范围异常。只有一个owner缺少完整release，
实际安全收尾已完成；缺失GPU-s仍未知，不补造、不按失败成本排名。

历史 `28b810d25c10245562c32a6a3b66f1f8b4dfe1a8` 已通过锁与退出标记保证
并发收尾只写一次退出事件；本次保留这项所有权与幂等性，不回退它。
旧测试将编号9876的句柄传给被mock的select，因此未检验真实内核接口的编号范围。

可证伪假设：合法pidfd只要编号达到select的范围上限，原收尾就会失败，
与模型推理是否成功无关。最小见证仅启动一个等待stdin的小型CPU进程，
使用 `F_DUPFD_CLOEXEC` 取得编号至少1024的同一pidfd，不创建千条连接或耗尽资源。
原代码在该见证中产生与D540相同的ValueError，已保存失败日志。

原始依据：Linux [select规范](https://man7.org/linux/man-pages/man2/select.2.html)
说明该接口的编号范围限制并推荐poll/epoll；
[pidfd规范](https://man7.org/linux/man-pages/man2/pidfd_open.2.html)明确支持
对原进程句柄观察内核退出事件；
[Python 3.12接口](https://docs.python.org/3.12/library/select.html#polling-objects)
定义poll事件与毫秒超时。不是按性能结果选择等待方式。

## 修复边界

只修改既有 `PhysicalGPUAllocation.wait_workers`：

- 对原先固定的pidfd使用poll，支持其合法编号；不重开PID、不改变进程身份。
- 保留一个共同绝对deadline和异步等待，不逐个worker重新给予完整超时。
- 全部退出事件收到后才记录一次 `native_workers_exited`。
- 无效句柄、错误事件和非退出事件明确失败，不能当作已退出。
- 后续release仍要求父进程退出、完整原生退出证据和实际空GPU检查。
- 没有固定sleep、异常吞掉、描述符强制重编号或猜测释放时间。

相同公共资源计量代码对所有使用它的系统生效，不只为S-LoRA特殊处理。
保持原60秒正常收尾时限；输入检查明确拒绝非有限或负时限。
毫秒向上取整仅对应poll接口精度，不放宽SLO或请求超时。
