# D955：7B 路由快照重叠验证的预启动状态

日期：2026-10-30

## 目的与执行边界

D955 预定使用既有 7B、500-adapter、`fixed_length_greedy_v1` trace 的前 100
个请求，验证 D954 中“native observation 与 confirmed file snapshot 可并行
等待”的单一假设。配置、模型、路由策略、交付模式和输出目录均为新的 D955
执行键；不覆盖 D931，也不改变远端服务配置。

  `d7acd08127d4f4513b23af6dd57a9647cf047570f2b563e361e716ccb0b32b83`。
- D955 输出目录在预检时不存在；未产生请求、GPU 进程、缓存或结果文件。
- 推理机根文件系统可用约 174,845,349,888 bytes（约 162.8 GiB）；四张
  RTX 3090 均为空闲。

  `/status` 与 `/manifest` 也没有形成可用服务证据。

  中的 `10.199.227.174` 入口同样没有在本机完成 SSH 握手。没有据此修改路由、

- 本机 `127.0.0.1:18081` 的 Docker 代理返回空 JSON；它不是
  `remote_artifact_node/server.py` 的 `/health` 响应，不能作为远端交付替代。

## 决定

D955 请求回放暂不启动。该决定由外部服务可用性决定，而不是新增性能门槛：若
在端点无响应时启动，失败时间、连接超时和错误重试会污染路由墙钟，无法回答
D954 的因果问题。配置和代码保持不变；远端服务恢复后只需重新执行同一 D955
执行键，并在请求前重新记录健康响应、交付模式、内容清单摘要和链路状态。

CPU-only 并行夹具与 44/44 路由/生命周期单测已经通过，但它们仅证明并行结构
和异常清理，不替代真实 100-request 证据。D955 未产生正式性能结果，不能用于
G1/G2、TTFT、GPU-s 或远端传输结论。
