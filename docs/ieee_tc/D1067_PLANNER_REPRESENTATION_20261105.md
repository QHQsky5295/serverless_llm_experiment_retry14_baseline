## 一个可证伪的候选

只在 CPU 组件中测试：保持标准 canonical JSON 编码、SHA 和相等性核对，
将这份已经编码的 JSON 的解析交给现有 msgspec JSON decoder。不改 encoder、
wire、source/plan hash、需求/成本、候选、预算、执行期实时校验或 IEEE 九式。
没有跨调用状态缓存、延迟观测、手工阈值、额外线程或异常时换回旧解析器。

这不是重新尝试 D192 的递归校验加 encoder，不是 D737 的延后 wire 解码，
也不是 D193 的字段投影或 D751 的 owner 图表示。D124 已消除了通用 deepcopy，
本次不重复它；仅检查其尚未更换的解码调用。若没有可测组件收益或值/类型/
浮点位/隔离/选择不一致，即停止该方向，不用完整 GPU 回放找收益。

官方参照（本轮重新读取）：

三个交错轮次、每轮五调用全部保留。以下是 CPU 组件调用均值，单位 ms；

| 已注册 adapter | 标准解析的完整冻结函数 | msgspec 解析的完整冻结函数 | 相对变化 |
|---:|---:|---:|---:|

| 24 | 26.105 | 19.824 | 减少 24.06% |

第一组候选三个轮次为 8.327 / 8.487 / 28.704 ms；不删除慢轮次，也不
在没有证据时将它归因为外部干扰。其余组节省约 3.36–6.28 ms。全部内容、
类型、字典顺序、浮点位、SHA 及四个 handoff/residency 夹具的完整执行包
相同。非有限数、非字符串 key、tuple 和循环仍拒绝。未配对 surrogate 在
旧解析器中接受、候选中拒绝，故不是对所有 Python JSON 字符串的无条件等价。

决定：**不接入生产、不为此启动 Full GPU 回放，不追加同类组件搜索。**
局部收益存在，但尚未证明它是 Full 净收益的关键障碍；完整函数含编码与
相等性核对，不能把 decoder 改动说成消除了重复状态工作。保留此次正反结果。

## 无动作规划的新增证据与下一主线

按实际 plan SHA 连接 CPU 回执、文件计划和 GPU 计划，而非按时间猜测。
2,139 个文件计划中，有 900 个同时满足：完成、文件注册 target=0、没有
对应 GPU 计划；其中 residency 899、handoff 1。对应 worker CPU 累计
176.045 s、均值 195.606 ms。这约占全部 owned_execution_epoch CPU 的
39.03%；是处理开销分解，不是可直接节省的 GPU-s 或请求时延。

该连接证明这些计划最后没有选中搬移，**没有证明原因**：它们可能是已有
GPU 命中、没有正增益、容量/替换不合算，或新需求窗口为空。现有薄日志不含
完整 frozen demand/source view；不能凭空恢复“所有正需求均 GPU-ready”。
899 次 residency 也不是 D1066 已跳过的 249 次 replica opportunity。

下一项只研究一个可证伪方向：从当前真实需求和当前已确认 native 状态中，
能否在全量文件视图/计划构造前证明零正增益，而不复用旧状态、改变观察时间、
减少安全校验或引入 TTL。先核查实际依赖及历史否定项；证据不足时不把该
条件直接上线，不用“空选择”冒充提前可知。D1066 与旧 A1 矩阵不覆盖或混合。

三个 CPU 域均正常退出：区间分析峰值 34,668,544 B，组件 703,250,432 B；
