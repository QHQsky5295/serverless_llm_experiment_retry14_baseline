# D933：7B 基线再入比较与 PrimeLoRA 当前位置

日期：2026-10-29  
目的：在不重跑或覆盖历史结果的前提下，将已完成的 7B W2 基线重新接入当前
PrimeLoRA 主线，明确哪些结论可以复用、哪些仍受合同或正确性字段限制。

## 结论摘要

7B 的 ServerlessLLM、vLLM、S-LoRA、HydraServe 和 Loquetier W2 完整观测已经
存在，均为 4,000 请求单轮结果，输入/adapter/目标长度和原生输出合同已有逐请求
核对。它们可用于当前阶段的机制与相对位置审计，不需要重新生成负载或覆盖旧
结果。由于历史结果的 `n_correct` 均为未知，所有物理 GPU-s 数只能先作为
`per-offered` 或原生合同分母的观测，不能冒称已经完成独立数值正确性核验的
G1 结果。

PrimeLoRA 当前最可比的 W2 观测是 D931，而不是 D932。D932 是入口诊断候选：
它完整、联合服务达成率较高，但物理 GPU-s 和尾延迟都比 D931、D917 更差，故
不作为新 PrimeLoRA 参考。D931 仍是“达到可比较服务可行性、但尚未证明 G1/G2
最优”的开发期候选；基线再入的作用是确定相对瓶颈，随后再决定是否提出新的
PrimeLoRA 控制/准备候选。

## 可支持的比较

1. 在这组已知 W2 观测中，vLLM 的联合服务达成率和 P95 TTFT 最好，但其物理
   GPU-s 高于 D931；PrimeLoRA 的 D931 物理 GPU-s 低于 vLLM 约 27.3%，P95
   TTFT 高约 71.1%。这只描述两次单轮观测，不是 G1 的独立数值正确性证明。
2. D931 比历史 PrimeLoRA D554 同时改善联合达成、物理 GPU-s 和 P95 TTFT，
   但 D931 与 D554 的源代码、控制初态和执行身份不同，不能把这种差异写成
   单一机制的因果增益。它支持“当前候选已达到可比较服务可行性”，不支持
   “PrimeLoRA 已经全局最优”。
3. ServerlessLLM、S-LoRA、HydraServe 和 Loquetier 的低联合达成不能被简单
   当作其论文算法本身的失败。已有文档记录了顺序启动、固定存储池、静态分片、
   轮询和单物理节点适配等实际部署条件；这些条件必须在论文中作为复现边界
   披露，不能偷偷优化对手，也不能把系统外部维护打包时间归入 PrimeLoRA 的
   优势。
4. D932 不应作为“日志 offload 使 PrimeLoRA 变快”的证据。它的入口诊断局部
   假设得到早期支持，但全量运行物理 GPU-s 为 13,777.448、P95 TTFT 为
   3,362.936 ms，均劣于 D931 和 D917。D932 保留为阴性开发证据。

## G1/G2 资格边界

- 所有行的独立数值正确请求数仍未知（`n_correct=null`）；不能以原生 token
  数量等于 target 推定 adapter 数值正确。
- D931/D932 均完成 4,000 请求且联合服务达成超过 95%，但这只解决共同服务
  合同的可行性观察。G1 仍要求正确请求分母下的物理 GPU-s/request；G2 还要求
  共同资源预算下比较 W1/W2 尾延迟，并另报联合达成率差值。
- 不能用 CE、美元成本、平均 TTFT 或低 `per-offered` 数值替代 G1/G2；也不
  要求未达 95% 的基线被删除。它们的失败和适配代价是比较证据的一部分。

## 下一步决策

1. 保存 D933 作为 7B 基线再入审计，不运行新图表，不修改历史结果。
2. 将 D931 作为当前 PrimeLoRA W2 的可比较开发候选；将 D932 标记为阴性
   诊断候选，不再重复其日志线程变体。
3. 接下来若继续优化 PrimeLoRA，优先从 D931/D932 已有阶段字段检验
   `dispatch/admission`、`runtime slot wait` 和扩容事件时序，而不是再改观测
   写盘路径。任何新改动都必须登记一个新的可证伪假设，并与 D931 的物理资源
   和尾延迟同时比较。
4. 在当前比较已经足以定位 PrimeLoRA 与 vLLM 的资源—尾延迟取舍后，恢复计划
   中的 W0/W1/G2、3B 和审稿人要求的消融；若后续基线或新 PrimeLoRA 候选改变
   G1/G2 排序，再回到 PrimeLoRA 做有证据的优化，而不是按单一指标无限调参。

## 远端交付与资源口径

所有可复用行沿用同一已发布只读 LoRA 集合；请求触发的远端读取、传输、竞争
和本地物化属于 TTFT/E2E，发布前一次性压缩和远端无关运维不从请求延迟中扣除。
制品节点容量使用并发临时打包峰值、日志增长和安全余量的独立规则；推理机
150/100 GiB、内存、OOM 和 cgroup 规则不变。D933 不触碰共享 k3s、远端服务或
用户 manifest。
