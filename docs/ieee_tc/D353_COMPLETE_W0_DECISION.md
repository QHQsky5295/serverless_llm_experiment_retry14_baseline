# D353：减少重复 HOST 清点后的完整 7B 结果

2026-10-08。原4000请求 W0、固定输出、真实远端已发布工件，普通测量，
未启用 D351 详细观察器。本轮执行提交为
`06ca566eb96eb1b619b7c4fd71d0db5da3d2c62b`。
这是一次开发回放，不是正式留出块，不计算单次运行的置信区间。

## 结论

**时延有所改善，但尚未达到 G1/G2；不关闭 7B 优化。**
相对直接参照 D349，平均/P95/P99 TTFT 和 TPOT 均改善，暂定联合时延
通过增加84个请求；物理 GPU 占用却增加17.78%。相对较早的 D336，
占用下降3.53%，但尾延迟和联合通过率仍退化。因此不能以胜过上一慢候选
替代超越此前 Prime，也不能用平均 TTFT 的改善抵消联合服务要求。

N_correct 仍未知，原生输出数量与控制绑定检查不自动成为独立数值资格。
共同最终 warm/Resident 参考仍未冻结。以下使用未改变的 D170 开发尺子，
是 timing-only 上界，不是正式联合 SLO 或 GPU-s/correct-request 排名。

## 仍存在的服务损失

固定原顺序8×500阶段的联合未通过数为
`20,114,22,27,7,14,31,13`；不根据结果重新切分。
第二阶段仍有87个 TPOT 超界、53个 TTFT 超界（26个重叠），平均
arrival-to-admission 1060.704ms，P95 TTFT 7121.945ms。
该阶段相对 D349 排队减少，但平均/P95 TPOT 为53.129/132.054ms，
仍略高于 D349 的52.457/126.558ms。不能把全程平均改善写成处处改善。

共同1114个2–32token短输出中，TPOT超界为 D336 77、D349 196、
D353 145；D353其余33–128和129–256组分别28、6个。短输出仍占
179个TPOT超界的145个。相同长度分组不消除实际队列/加载/闭环差异，
不据此单独确定 CPU、prefill 或启动的因果贡献。

本轮实际2584次命中事务复用、1416次完整后检查，分类冲突0。
dispatch GPU tier为2572次，少于 acquisition 时已确认命中的2584次；
期间合法准备可使状态变化，不回写 dispatch 快照，也不将两者强行等同。
该计数证明机制触发，不等于已量出可归因的延迟收益。

1875次控制观察记录16次扩容、13次回收。物理区间并集验证：
`13326.570890 = 15845.251396 envelope − 2518.680506 实际释放间隙`。
相对 D349 的 U 增量2011.687933，由持卡首末边界包络增加1792.718658、
中间释放间隙减少218.969275构成。只是已观察轨迹的恒等式，不是反事实。
不能把单请求清点次数减少自动推导为生命周期 GPU-s 减少。

## 完整性、安全与失败保留

- 4000个请求的身份、工件内容、owner/lease/native slot、持有/释放和
  token摘要传输检查全部通过；时延阶段恒等式误差0。
- 相对 D349/D336 分别167/247条输出SHA不同，完整清单保留。此前 D295
  已显示同后端数值重复性不能简单由批处理解释；本轮不重开没有新假设的
  数值重复或PEFT测量，不由名称/slot正确推出独立算术资格。
- 132次真实远端获取、131480060线上字节，双端ID/SHA/字节对应，
  请求内打包和临时归档均为0；复用已批准只读交付缓存。远端1000/full
  是启动前链路协商状态，不等于应用层达到1Gbps。
- 4030个资源样本，服务峰值22306799616B，主机最低可用92741730304B，
  high/max/OOM/OOM-kill/实验swap均0。实际GPU释放、服务域移除、远端
  三个本轮服务停止及端口关闭均已核验。
- 初次分析100项测试通过，完整统计和D349对照成功；D336对照在旧入口
  白名单处失败，未生成其输出目录。修复统一登记后103项测试通过，只补
  剩余D336对照。保留初次失败、旧分析源SHA与原文件，不重算或覆盖已完成
  的D349对照，不重跑GPU。初次离线峰值1021239296B、无内存事件。
- 收尾后无损压缩六个已关闭的历史 main_outcome 日志；逐份验证原SHA、

## 下一步与主线

本轮关闭的是一项候选的完整验证，不是7B优化。保留 D352 的安全机制证据
和本轮收益/退化，不将该配置冻结成“最优”。不重复D353寻找胜出，不继续
盲扫软目标、容量或固定token预算；也不放宽共同尺子。

下一步先复用现有 D353 与 D351/D350 的阶段、闭环、native控制与decode
证据，定位第二阶段和短输出的剩余损失，再结合历史失败和原始官方实现
选择一项可证伪优化。任何新修改都须保持九式、真实物理安全和当前计量
口径；最小验证后才做普通完整回放。尚不推进3B、外部基线、M1/M2、
消融或敏感性，这些已批准任务全部保留。暂不生成性能图。
