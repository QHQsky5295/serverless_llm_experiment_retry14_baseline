## 不能省略的初始化差异

与D423的历史同配置启动记录相比，D532四引擎约143秒才就绪，D423约41–42秒。
两者任务到达视图不同，因此不作同负载性能归因；但引擎初始化在服务请求前，
这一差异必须单独解释，不能把全部延迟退化归于W1突发。

已核查的事实：

- 引擎参数一致，现有原生测量快照中的三个源码SHA一致；这不代表所有依赖
  和环境状态逐字相同。
- 两轮日志均从相同AOT路径加载，torch.compile约0.3秒，并非已证实的AOT miss。
- D532四引擎初始化报告111.57–111.97秒；D423 worker0为9.59秒。
- D532的JIT-warmup-finished行在00:33:37，后续graph-finished行在00:35:21，
  但graph内部计时仍为2秒。仅凭这两个日志边界不能确定耗时属于哪一调用。
- 本地源码与[官方v0.30 GPU worker](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/v1/worker/gpu_worker.py)
  的初始化顺序表明V2 `warmup_kernels` 位于相关边界间；这是候选核查路径，
  不是已观测的因果耗时。缓存命中不等于所有warmup成本相同。
- 首500请求仅1条联合达标；其后各500请求分别为367、294、345、400、384、379、485。
  全部阶段保留，不能丢弃首阶段或只用末段97%替代完整66.375%。

原因目前未知。没有据此判定运行无效、修改参数、放宽SLO、追加重复或扣除
初始化延迟。现有完整结果先封存；W1参考冻结暂不执行，先核查已有源码、
