资源生命周期相对四实例常驻节省多少物理 GPU 时间，时延和联合 SLO 如何
变化？FixedFull 是常驻资源对照，不是外部 baseline，也不是新的优化候选。

## 机制和计量证据

- FixedFull 恰有四个 initial activation、四个物理 allocation，均实际服务
  且释放；natural_scaleout、scale-up、scale-down 均为 0。Full 为 1 个
  initial、9 个 natural_scaleout；first-service 只绑定首条实际 dispatch，
  未用 initial 样本充当自然扩容样本。
- FixedFull 保留 3,093 个稳态 residency epoch；3,097 个文件准备计划中
  4 个来自 initial handoff，其余来自 residency。1,849 个 GPU 准备计划和
  1,362 条 native HOST 准备记录均来自 residency。没有自然扩容就没有相应
  GPU handoff 记录，不能从启用开关推定其产生了性能收益。
- 两点均保留 Full 软 admission；FixedFull 1,333 个实际 typed decision
  全为 admit，观察到的软 headroom deficit 为 0。不将该运行冒称 S3 争用
  验证。计划/attempt 数不是唯一物理加载数。
- dispatch tier 覆盖 4,000 条：FixedFull GPU 3,299、NVMe 567、remote 134；
  Full GPU 3,327、NVMe 538、HOST 2、remote 133。tier 是所选副本快照，
  不应与全服务 132 次 fetch 数强行相等。
- 全部 4,000 条 request、adapter、source item、prompt token/hash、target、
  原生数量和生成合同匹配。输出摘要 3,789 条相同、211 条不同，逐条差异
