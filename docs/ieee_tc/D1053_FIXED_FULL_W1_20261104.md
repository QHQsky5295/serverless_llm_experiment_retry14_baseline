## 科学问题与唯一差异

在 readiness routing、handoff、层级驻留及 admission 全部保留时，弹性
资源生命周期相对四实例常驻节省多少物理 GPU 时间，时延和联合 SLO 如何
变化？FixedFull 是常驻资源对照，不是外部 baseline，也不是新的优化候选。
它与后续 ElasticOnly 等对照共同回应两轮审稿，不凭本点单独分解全部机制。

从 D1047 Full 配置仅将 min_instances 从 1 改为 4、max_instances 从 3 改为 4，
另换独占输出/NVMe/HOST 路径。不设置 dynamic_scaling=false；相同 IEEE
控制器继续采样并执行稳态驻留，实例边界阻止扩缩容。四个 initial activation
通过相同原生 owner 发起；准备从共同部署通知开始计费，第一实例 ready 后
即可服务，其他未就绪实例不虚构 ready，也不平移业务到达原点。

不改变九公式、Full handoff、软 admission、native victim、请求驱动预取、
排队/可行性/引用保护、profile、后端、generation、远端交付和资源包络。
D1052 的激活 capacity_only 参数透传补全已经提交；Full 的有效值仍 False。
本轮无生产代码修改，不借消融进行新的性能配置搜索。

## 完成后的解释规则

先检查全部终态、实际原生 token、输入与输出摘要、原生绑定、dispatch tier、
真实 allocation/release 与资源事件。必须核对四个 initial activation 的
实际 ready/持卡区间、自然扩缩容是否为零、稳态控制/驻留和 Full 准备路径
是否仍实际执行。未触发的机制不补写，启动后出错的实例不算正常常驻。

复用 D1052 collector/比较入口，只针对 FixedFull 的 min/max 和实际实例轨迹
调整分析，不改变冻结指标。报告共同 SLO、生命周期 GPU-s/offered、P95
TTFT/TPOT、平均 E2E、fetch 次数/字节与完整阶段，差值方向保持一致。
每个 execution key 一轮，不加 CI、重复均值或按胜负挑运行。

n_correct=null、independent_numerical_proof=false、formal_ranking_eligible=false
继续保留。3B 全零更新池不能证明非零 LoRA 算术；输入/长度匹配不替代数值
正确性，同后端输出 digest 变化另报。真实远端没有连续 CPU/外部干扰监控，
保留同 Full 的 existing_unmonitored 限制，不能宣称排除了所有远端干扰。

本文件预登记时尚未启动 D1053 GPU，不预写性能结论。当前结果比较与代码
备份分别有独立身份。用户 dirty 的 EXECUTION_STATUS.md 不覆盖；本文件
和 D1052 是当前交接，不能回到该旧文件头部 D998 的历史阶段。
