# 基线适配的停止规则与实验主线（2026-10-16）

用户在D587 Loquetier W1运行期间进一步明确：基线只需排除不合理复现造成的
异常结果，实验章节能结合机制、方法、研究背景和实际数据解释效果即可；
不得无限制优化基线，应将精力放在完整实验主线与PrimeLoRA。

本规则覆盖此前Loquetier专项优化/HydraServe适配许可中可能被误读为无限优化
的部分，不取消既定比较、正确性、安全、消融和敏感性内容，也不追改历史身份。

## 执行判据

1. 先排除有证据的输入/生成、adapter绑定、计时/资源计量、必要机器适配和
   安全问题。发现具体错误时，只修复必要路径、做最小资格并重跑受影响键；
   保留原运行，不把修复前的不合理低性能作为PrimeLoRA优势证据。
2. 核心机制已忠实保留、实际执行范围清楚且结果可由数据解释时，停止基线
   性能优化。解释需有队列/启动/加载/生成/资源或机制事件证据，不能仅以
   “原机制缺陷”或“硬件不同”作为无证据断言。
3. 低联合SLO、未过95%、某指标弱于PrimeLoRA、机制在本场景未触发，均不
   单独构成继续优化的理由。95%不是基线纳入门槛；原始表现和适用范围完整
   报告，不虚构原系统全局最优或断言其他硬件也同样差。
4. 不追加基线参数搜索、不反复跑同键寻优、不为触发机制持续更换部署形态。
   单物理机逻辑节点诊断的已完成证据可复用；不把逻辑节点宣称为独立物理机。
   既定机制实验仍保留，但不得借其名义无限延长平台适配。
5. 结果仍有具体、无法解释的正确性/计量/适配异常时，明确记录未解问题，
   不能仅以“已优化足够”强行关闭。检查应有范围和停止条件，优先复用日志。
6. 同配置完整矩阵及原计划必要实验照常完成；停止无界优化不等于省略W1/W2、
   3B、dLoRA限定比较、A1–A5或S1–S13，也不改变冻结G1/G2评价尺子。

## 对当前工作的影响

- D587 W1原配置继续执行，不取消、不重启、不修改服务和远端，不在运行中
  扫描、清理、构建、推送。当前仍是单轮观察，不构成最终结果。
- 其后审计、保存；完成同一容量配置的Loquetier W2及剩余必要7B对照。
  不因这些运行的胜负再开新Loquetier批量/分片/启动调优系列。
- HydraServe已完成的必要隔离、生命周期适配及W0/W1/W2证据继续复用；
  未触发的pipeline/consolidation范围明确披露，不重新开始无变化的基础资格。
- 汇总全部可用基线后，集中依据日志、代码历史、原始论文/官方实现和可证伪
  假设优化PrimeLoRA。完整未完成范围不缩减。
