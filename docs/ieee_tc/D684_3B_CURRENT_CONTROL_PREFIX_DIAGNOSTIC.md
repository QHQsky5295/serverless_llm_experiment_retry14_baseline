## 问题、历史与停止边界

D683显示306条联合违约不与自然扩容区间重叠；142条TPOT违约中131条输出
不超过31 tokens，其中58条dispatch时已GPU-ready。剩余违约不能都归为
远端传输。`runtime_slot_wait`还含路由、状态确认和保护，不是纯容量排队。
D682没有diagnostic_core；D668详细CPU测量早于D671独立HOST对象、D675主动
准备合并和D680需求HOST交接，不能将它的耗时直接当作当前瓶颈。

可证伪问题：在当前完整事务中，哪些控制操作占用native core执行线程，
是否与短请求decode重叠？重点核对fresh inventory、保护/释放、加载等已有
操作，同时保留模型执行、外部等待与观察器写入。若观测未显示控制干扰，
不据旧剖析继续优化HOST，不通过更改阈值或重跑同前缀寻找支持。

既有D329跨请求图缓存、D333中间状态盲融合、D595并发压力屏障、D628锁外
验证的否定证据继续有效。此次不重试上述设计，不改九公式、策略或控制参数。
