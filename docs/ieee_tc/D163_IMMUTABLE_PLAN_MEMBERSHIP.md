# D163：不可变计划成员查询的表示成本

2026-10-02，Prime 7B 单候选开发资格已通过。尚未完成普通 Full，不能声明服务收益。

## 问题与唯一修改

D160 的普通 Full 仍有请求路径等待；D162 当前版本诊断中，538 个控制器业务
样本有 20 个经 `Mapping.__contains__ → __getitem__ → snapshot → execution_copy`
解码整份计划。当前执行入口先查 `source_view` 是否存在，随后仍需打开同一
计划的 execution bundle。栈出现次数不是 CPU 百分比，也不是全部等待归因。

假设：成员查询只需要不可变键元数据；取消其中的完整解码，可以减少事件
循环同步工作，但能否降低完整回放的 TTFT/GPU-s 必须另测。

只为 `ValidatedPreparationPlan` 增加不可变键索引和 `__contains__`。索引来自
同一已验证 worker 事务的实际 `plan_keys`，采用无外部可变别名的只读 dict
视图；不保存或复用任何跨时刻 residency 状态。保留原 `plan_sha256` 快路径、
dict 的键哈希/相等及不可哈希键异常、原迭代顺序和所有脱离式导出。普通
mutable/imported plan 仍走完整验证，执行时仍解码其私有副本。

九个公式、目标/选择、profile、并发、超时、实时 owner/epoch、reservation、
取消和物理检查均不改。没有新增 worker、异步兜底或陈旧来源缓存。RPC 编码
及 GPU HOST inventory 是其他观察线索，不在本候选中一起修改。
