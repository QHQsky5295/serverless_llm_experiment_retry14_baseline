## 解释边界与下一问题

第一请求 TTFT 从 11244.304 ms 降至 6847.902 ms，但仍超过原在线控制的
5000 ms。实际后三卡从业务后 10.703/12.761/14.866 秒持有，D726 为
14.905/16.978/19.046 秒；两轮都持有至约 3976 秒、没有缩容。
这直接解释本轮没有物理资源节省；精确控制触发归因仍须复用 D727 观察器
检查本轮快照，不能直接把上一轮触发条件当成本轮实测。

本轮 371 条联合违约分为 TTFT-only 229、TPOT-only 120、both 22。
251 条 TTFT 违约中，GPU/HOST/NVMe 分类为 64/70/36，共 170 条；remote
为 81 条。dispatch 的 133 个 remote 分类与 132 次实际 fetch 定义不同。
不能把本地命中请求的等待称为纯远端链路瓶颈。

已有同钟阶段分析显示：GPU-hit 总 slot 等待均值 289.574 ms（D726 为
260.004 ms）；全体 arrival-release lateness 为 152.502 ms（原 129.341），
native prefill 为 106.026 ms（原 103.722）。这些是阶段包络和条件观测，
不是函数剖析；routing 嵌套其中，不能再加一次。下一步只复用本轮与 D727
已有数据，定位 steady-state release/slot/native pending 返回路径及控制
反馈，再结合历史失败和官方实现提出一个不同候选。不复跑同键，不叠加
未经验证参数，不从首请求中扣启动时间，不改共同 SLO、准备窗口或九公式。
