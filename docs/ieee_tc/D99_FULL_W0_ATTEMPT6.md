## 原因及边界

主异常是 GPU 准备执行中的 `ValueError: planned native HOST source changed;
next planning epoch required`。实际路径为 movement 执行 → GPU/file 准备收尾 →
驻留任务回收 → 全局回放退出。外层随后记录 external replay failed、
protocol_or_launcher_error、service returncode -15；这些不是应替代原始异常的原因。

该检查在同 owner/clock 的原生观测后发现目标来源不存在或名称/路径不一致。
现有异常文本没有区分这两个具体谓词，不能臆断是某种驱逐、错误 adapter 或
硬件故障。此次失败入口不同于 D98 的文件后备引用 hold；D99 只修正后一入口，
不能据 CPU 测试宣称所有动态计划失效场景已处理。

中断前已观察到长等待：11:36:15 有 302 条待完成，最早未完成请求年龄约
416 秒。它不是该请求最终 TTFT，成功子集也不能代表完整负载。需要后续阶段
分解，而不是将“避免退出”直接当作服务质量改善。
