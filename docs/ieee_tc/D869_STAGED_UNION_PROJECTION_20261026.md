# D869：同一次清点生成两个 HOST 视图，完整性能仍待验证

2026-10-26。主线仍是3B W2的联合SLO与生命周期资源目标；本节点不是新主结果。
HydraServe既有隔离适配继续复用，不接管不属于项目的k3s，不重启基础资格。

## 假设、历史与语义

D868已证明当前有真实暂存权重，并定位到完整来源查询在有暂存时重复遍历
registered图；其出现频率不能由416条请求预算回执直接推出。D671仅优化了
无暂存复制，未合并有暂存路径。D329禁止的跨调用状态缓存、D864整图模式、
已否决的线程/stat/文件projection/解码延后/全局GC调参均未引入。

本候选只改变同一串行查询中的工作复用：一次新鲜registered+staged清点，
保留union供allocator计量，再诱导出独立的registered图。每个实时tensor的
pinning、storage容量、表示及非法字段仍检查；allocator仍新读。不是按adapter
名义字节相减，也不把共享storage当作单个adapter可回收容量。

registered图过滤staged owner，删除仅staged可达的allocation，重编号全部
边，并按剩余owner重算独占容量。编号仅限图内，不进入成本/排序决胜；测试
覆盖staged ID在前、中、后、alias、private、仅暂存存储、空注册集合以及
两返回值所有可变容器独立。原生消费者的footprint、GPU fallback cost和
HOST replacement cost保持一致。无暂存和routing路径不增加第二次清点。

本轮核查的原始依据：[vLLM 0.30 LoRAModel](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/lora_model.py)
明确clone共享底层tensor；[管理器](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/model_manager.py)
和[Python复制语义](https://docs.python.org/3.12/library/copy.html)用于核对所有权边界。
vLLM技能用于这一核对，不采用其通用阈值/调参建议。九公式、配置、profile、
负载、SLO及远端交付均不变。

## 已完成的验证及全部观测

323项CPU回归通过。复用已有资源限制/外置watchdog和D747原生逐tensor描述器，
在真实3090上下文测两个HOST视图的总操作，未加载基座模型、未创建工件池，
未重放任何请求。小fixture沿用D747/D864：8个注册adapter×32层，packed与
alias视图共1536，另一个暂存clone共192视图；参考双遍历检查3264视图，
候选单union检查1728。pin检查实现未改，复用已有资格，不重复九种pin状态。

每个诊断执行预先固定20组交替次序；不是20次独立系统实验，不计算CI。

| 观察条件 | 路径 | 均值ms | 中位ms | 最大ms |
|---|---|---:|---:|---:|
| 原组件测量 | 两次新鲜清点 | 9.769268 | 9.840019 | 10.305235 |
| 原组件测量 | 一次union＋投影 | 18.394101 | 5.806455 | 257.164301 |
| 仅增加GC观察器 | 两次新鲜清点 | 9.814303 | 9.815173 | 10.223903 |
| 仅增加GC观察器 | 一次union＋投影 | 19.813485 | 5.755045 | 285.902310 |

两次诊断各19/20组候选较快，但原测量均值反而增加约88.3%，不能只选中位数
宣布净加速。原index15长停顿未插桩，原因保持未知。针对这个具体问题只追加
一次既有D686 GCObservation，不改回收开关、阈值、freeze或手动collect。

带观察器的index15候选285.902310ms中，generation2/0回收交叠279.516048ms，
占97.766278%。这是第二次诊断的直接证据，不能追溯证明第一次原因，也不能
将交叠从时延中扣除。观察器可能改变触发位置；完整逐调用数据和两个结果均
保留，不合并挑选较好一轮。分析技能要求分开观察与推断，因此没有把减少
重复检查次数直接换算成SLO、GPU利用率或用户时延收益。

## 裁决与下一步

候选的语义与原生可执行性已通过，**尚未证明净性能改善，不晋升最终配置**。
局部验证到此停止，不继续GC或描述器微调。两次均值较差与多数调用变快并存，
而本组件没有执行真实EngineCore启动后的堆状态（已有差别见D686），不能用
此小fixture直接判定长时间服务收益。下一步只做一次新键的完整3B W2回放，
采用默认D747逐tensor描述器、现有D857/D858配置，加本次单一改动；不叠加
D864 graph候选、不增加100/1000请求过渡回放。完整结果决定保留/撤销。

采用冻结V1＋单轮V2：全部请求/原生计时与身份、联合至少3800/4000、物理
GPU预算，原始延迟和失败均保留；不放宽SLO、不调在线扩容线、不删除首请求。
原D858和D866不同候选结果保留。当前最新完整D866仍3748/4000=93.70%，
11936.678203 GPU-s（预算12083.063870）；独立数值正确性未知，G1/G2未完成。
