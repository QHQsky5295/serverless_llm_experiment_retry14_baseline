# D401：ServerlessLLM 物理 GPU 计量接入与副本来源核查

日期：2026-10-11。主线仍为已封存的 7B PrimeLoRA W0 观测之后，先核查
ServerlessLLM，再进行 7B 同合同对比。本次没有运行新的 GPU 性能实验。

## 本次解决的测量缺口

D398 已复用历史日志证明：ServerlessLLM 的原生存储服务会建立多卡上下文。
因此，推理副本缩容不等于物理 GPU 释放，不能仅根据副本数量计算资源收益。
另一个问题是，实验结束时已经退出的副本无法再通过实时查询取得来源证据。
两者分别影响资源计量和实现可追溯性，不能互相替代。

本次只扩展 baseline 已有资格入口，不改 PrimeLoRA、论文公式、原生路由、
扩缩容、加载或生成策略，也不新增实验框架：

- 原生存储与推理进程共用已有物理分配账本；同卡占用取并集，不重复计费。
  独占资源从原生服务启动前的真实分配开始，前面的 CPU-only 配置不计 GPU。
  这一固定存储资源池的部署方式明确披露，不外推为所有 ServerlessLLM 部署。
- 每个服务副本在开始接请求前，保存实际 PID、启动身份、资源域、CPU 约束、
  后端与存储源码 SHA、checkpoint、原生加载模式的只读凭证，并绑定到请求。
  正常缩容后仍可核查，不再要求已经退出的副本保持可查询。
- 资源释放必须通过内核进程退出通知和新的 GPU 上下文核查。未证实释放则
  保留占用未闭合状态；启动未完成时不虚构“空进程退出”证据。
- 使用同一真实开放回放的终态与输入身份。失败和取消保留；缺失终态、缺失
  释放不能产生完整低成本结果。输出 token 合同不是数值 LoRA 正确性证明。
- 完整资源摘要绑定不可变原始结果 SHA，允许后续统一离线指标读取。

NVML 只提供实际进程上下文信息，不能单独替代分配与释放记录；本次沿用
现有计量模块，未用秒级采样伪造精确边界。
[NVIDIA 文档](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html)
