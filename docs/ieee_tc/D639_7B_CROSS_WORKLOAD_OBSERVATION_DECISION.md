## 3. 全部五个已发表baseline的比较，不隐藏取舍

来源仍为D593完整7B表，15个外部baseline点全部保留。新分析文件逐项保存
绝对值、PrimeLoRA相对资源/尾延迟变化、SLO百分点差及预算可行性。

- **W0资源效率：**PrimeLoRA在98.375%联合达成下，比vLLM少42.955%物理
  GPU时间，比ServerlessLLM少42.864%。但其P95 TTFT分别高68.660%和92.424%，
  联合达成相对vLLM低1.100个百分点；不能说所有延迟指标都领先。
- **W1扩容负载：**PrimeLoRA联合96.050%，五个baseline的既有工作点均未达
  95%，且均高于共同75%预算。PrimeLoRA的资源和P95 TTFT在这些观测点均较低。
  这支持所测工作点的资源—服务质量优势，不证明每个baseline不存在其他
  可行配置，更不是大规模集群的全局最优。
- **W2高churn：**PrimeLoRA联合96.350%、U/预算0.902994。vLLM联合98.225%、
  P95 TTFT 1751.295ms，比PrimeLoRA更好，但其资源超出共同预算；PrimeLoRA
  少用32.275% GPU时间，联合低1.875个百分点。HydraServe资源比PrimeLoRA
  更少并在预算内，但联合仅66.000%。不能把这两种不同取舍删掉后宣称
  “PrimeLoRA所有指标第一”。

G1的共同质量约束、G2的预算/质量约束与“相对baseline联合达成不低于”分别
报告。这里只有PrimeLoRA观测点同时满足W1/W2的两项数值约束，缺少多个
可行对手点，因而不能声称已证明完整的同预算尾延迟支配关系。
没有CI、显著性或未测配置的最优性结论；不据胜负修改95%/75%阈值。

## 4. 阶段决定：封存7B当前点，推进3B，不再循环W0资格

接受这组**有明确版本边界的7B开发观测**作为后续比较与实验设计的依据。
同后端输出有界审计现已覆盖W0/W1/W2；不存在本次发现的具体绑定错误需要
立即修复。D637的R2影响说明与D638/D639数值局限一起引用，不把R2改为R0，
不将三个旧运行冒充同一个修复版本的正式执行。

停止为“输出必须与HF逐token全等”或单项TTFT必须击败常驻vLLM而重跑7B。
后续新发现具体异常或确需同版本机制对照时，只补受影响实验键；不能用
既有不同版本数据伪配对。核心消融Full与最终主表的canonical run-set仍须
按最终同合同要求选择，不能手工对齐数字。

**下一主线为3B。** 先读取D274/D138等已有历史与最新源码，确定IEEE Full的
完整3B配置和测量合同，复用现有模型、500-ID池、trace、环境与远端发布缓存。
旧3B约12.6秒平均TTFT不能作为当前版本结论；也不能把7B的14-slot配置直接
称为3B最优。先有界资格/profile检查，冻结共同warm阈值和Resident参考，再
做当前3B完整比较与有证据优化。每次新优化继续遵循历史＋原始论文/官方源码
＋可证伪假设＋最小验证，不越过公式、资源安全和版本记录。

此阶段决定不是整个7B研究目标、G1/G2全局最优或整体计划完成。3B全部系统、
dLoRA限定W1/W2、A1–A5、S1–S13、成本敏感性、B1/B2/C1/C2/C3及两轮审稿
文档、最终学术图表与交付均保持ACTIVE。不重启已完成HydraServe基础适配，
不触碰其他项目k3s，不恢复无限baseline调参。
