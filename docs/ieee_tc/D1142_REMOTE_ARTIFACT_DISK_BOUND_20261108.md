# D1142：远程制品节点独立磁盘门禁（2026-11-08）

状态：实现与静态验证完成；本记录不启动远端服务、不改变远端文件、不启动 GPU 回放。

## 判定

计划 §2.9 已批准制品专用节点采用独立于推理机的容量规则：

\[
D_{free} \ge R + \left\lceil 1.5(P+L)\right\rceil,
\]

其中，`P` 是所有同一文件系统上并发临时打包的剩余归档字节上界，`L` 是运行期间日志增长上界，`R` 是正的安全余量。推理机的 150 GiB 启动门槛、100 GiB 运行底线以及内存/OOM 门禁均不变；本规则不替代这些推理机规则。

本轮真实远程性能入口使用 D80 已发布的只读 gzip 缓存，请求路径不再打包，因此冻结：

| 量 | 冻结值 | 依据 |
|---|---:|---|
| `P` | 0 B | 请求路径复用 immutable prepublished gzip，不创建临时归档 |
| `L` | 1 GiB | 覆盖本轮完整 W2 服务与监控记录窗口的保守日志上界 |
| `R` | 16 GiB | 保留远端系统/无关任务恢复余量 |
| 要求空间 | 18,790,481,920 B | `R + ceil(1.5×(P+L))` |

运行监控在服务启动后立即检查该容量，并每 30 个采样周期重新检查；它同时检查可用 inode、服务 cgroup 的内存上限和 swap 配置。检查失败只停止本次受控服务，不删除任何制品、不压低并发、不修改共享 k3s。

## 实现绑定

- `scripts/ieee_tc/monitor_remote_artifact_service.sh` 现在要求调用方显式传入 `P/L/R`，并记录计算出的 `artifact_disk_required_bytes`。
- `scripts/ieee_tc/run_d1100_7b_busy_service_rate_w2.sh` 为 prepublished-gzip 合同传入上述冻结值。
- `scripts/ieee_tc_preflight.py` 的 `artifact_disk_required` 与该监控使用同一整数上取整公式；推理机 `disk_required` 未修改。

## 证据边界

这次改动只修正远程制品节点的资源资格判定，不宣称远端已经完成新的性能测量，也不改变任何历史结果、工件集合、请求负载或论文主结论。真正的远程 Full 回放仍须在启动前重新读取当前容量、inode、链路和内存状态，并把完整传输、读取、竞争和本地物化时间计入端到端结果。
