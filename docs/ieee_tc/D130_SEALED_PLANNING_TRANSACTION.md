# D130：合并冻结计划的生成与纯验证事务

状态：开发候选。组件测量及最终回归完成；尚无 D130 完整 Full 结果，
不能声称系统延迟、SLO 或 GPU 占用改善。沿用冻结指标 V1 和 IEEE 九个公式。

## 1. 为什么继续检查这一处，而不增加另一个优化

D129 普通 7B Full 的 4,000 请求有 3,415 条原生生成合同成功、568 条超时、
17 条所有权未解决错误，未通过全部正确完成门槛。成功子集的平均 TTFT
999.694 s；不同运行的成功子集不相同，不能把它与 D125 的差值当作因果估计。
D128 的小型 CPU 分离实验没有转化为已证明的 Full 收益。

D129 实际记录了 4,240 次规划 CPU 调用：2,123 次构造/选择和 2,117 次纯验证，
同一服务内共传递 23,358,761,432 B 的输入/输出。构造与验证的平均总调用时间
分别为 1,567.942 ms、2,183.526 ms，其中包含排队、通信、计算和父进程返回。
这些调用可以重叠等待，不能把均值或累计时间直接加到用户 TTFT。
这不是远端 LoRA 下载字节，也不是 GPU 账单。

源码对应的冗余边界是：子进程产生完整计划 → 父进程解码 → 把完整计划再次
发送到同一个子进程 → 再次返回计划及验证后的选择。两个纯计算步骤之间
没有必须由父进程修改的计划内容。动态资源检查在后面的实际执行路径中。

可证伪假设：在同一不可变 epoch 中保留原构造与原纯验证，但合并其通信事务，
可以减少完整计划的拷贝/传递和第二次排队；是否降低系统排队必须由普通
Full 验证。它是 D128 同一架构候选的针对性替换，不叠加独立调参或 codec。

## 3. 论文规范与实现证据

| 必须保持的语义 | D130 实现 |
|---|---|
| 同一 epoch 的需求、成本和收到的物理视图 | `freeze_owned_planning` 在首次 await 前采样；未读取未来请求 |
| 原收益、逐层选择、DP/greedy、tie-break | `owned_execution_epoch` 仍调用原 `generate_ieee_epoch` 和 `validate_ieee_execution_plan` |
| 纯验证不可跳过 | 原 validator 仍重算选择并核对完整源视图；不是省略算法验证来换速度 |
| 对外修改不能继承“已验证”状态 | `ValidatedPreparationPlan` 保存 bytes；读取/深拷贝导出普通独立字典；导出物再次执行时必须完整验证 |
| 计划不等于资源租约 | live owner、epoch、content、budget、引用、reservation、registration 和实际加载检查不变 |
| 取消不遗弃 CPU 工作或发布结果 | 运行中的计算 join 后丢弃；排队取消不提交；原资源生命周期与收尾不变 |
| 相同计划可用于受控 handoff | 每次执行解码独立副本，保留同 plan SHA；物理状态变化仍可能拒绝或 supersede |

只修改纯规划接口及其消费者，不改 planner 公式源码、并发容量、线程数量、
超时、安全阈值、生成合同或远端交付方式。单 worker 仍在服务资源域中，
冷启动仍计入系统准备时间。pickle 只用于可信本机父子进程，不接收远端 pickle。

封存类型是内部表示合同，不是对任意恶意 Python 代码的安全隔离。
原同步 API 和普通历史/外部字典仍走显式完整验证路径，不是异常兜底。
正式日志只保存 SHA、计量和执行事件，不序列化封存句柄；诊断需要普通
字典时显式导出，导出成本没有从测试中暗扣。

代价必须保留：activation 的纯验证现在先于引擎启动；过去它可能与引擎
初始化重叠。合并事务可能减少 IPC，却增加启动前等待。完整 Full 将检验
净效果，不能只根据字节减少接受优化。

## 4. 组件结果与表达方式

复用 D128 的四 adapter owner fixture 和三次交错暖态测量。所有计划、源 SHA、
选择及输出值完全一致。无 GPU 推理或远端性能运行，不生成新的模型/完整负载。

| 指标 | 原两次往返 | 合并封存事务 | 相对变化 |
|---|---:|---:|---:|
| 暖态总调用时间，ms | 6.900001 | 2.930867 | 降低 57.52% |
| ready callback 等待，ms | 0.190854 | 0.243885 | 增加 27.79% |
| CPU 事务数 | 2 | 1 | 降低 50.00% |
| IPC 输入字节 | 21,117 | 6,999 | 降低 66.86% |
| IPC 输出字节 | 28,283 | 14,142 | 降低 50.00% |

首次进程启动及首事务共 12,899.238 ms，单列保留；不是从生产生命周期排除。
三次本机组件重复不是独立 workload seeds，不生成系统级 CI。
本表同时展示改善和退化，适合精确比较通信量/调用时间；按 academic-plotting
及计划 §11，不将小型资格证据画成暗示 G1/G2 领先的主图。

组件结果只支持此表示变化减少了两次往返，不能证明 500 adapter 下的幅度，
更不能解释全部积压。已有 D129 实际大规模证据说明不能外推四 adapter 微测。
