# D483：存储维护与复现保护（2026-10-13）

本轮遵循用户最新的 storage-first 要求。不是性能实验，不改变冻结指标、
系统排名、成功/失败身份或任何模型/LoRA/负载。

前后检查不变；源文件只在完整验证后移除，内容在同目录 `.gz` 中保留。

活动变化，回收量按原文件/归档实际分配块差计算，不用 `df` 差冒充精确归因。
压缩任务内存峰值 439,107,584 字节，high/max/OOM/swap 事件均为零。

## 盘点结果与保留决定

复用 2026-09-15/16 存储审计和清理程序的准则，重新盘点当前目录，未重跑
历史删除清单。历史已释放的空间不计入本轮。

- baseline `results` 当前约 722.62 GB，其中旧远程 baseline 组约 271.91 GB；
  很多是逐运行 remote_cache。9 月审计已发现后续输入路径引用，不能因为
  名称为 cache、文件旧或表面上重复就删除。尚未完成新的逐项核验，全部保留。
- PrimeLoRA 的 `p2_backend_qualification` 约 217.24 GB；进一步定位到大量
  9–15 GB 原始输出 JSON。它们是历史测量证据，采用无损压缩，不删除字段，
  不以 compact/projection 摘要替代原文，不按结果胜负选择。
- pip 缓存当前仅约 42.7 MB，9 月“约 51.89 GB”的历史数值已不适用。
  不为追求清理数字删除仍可能支持离线复现的小型依赖缓存。
- conda 包目录约 39.04 GB，可能与多个环境共享硬链接；不直接按目录
  表观占用宣称可以释放，不删除仍被环境使用的包或 CUDA 工具链。
- D482 已取得的 Torch/xformers 与已有 CUDA 12.4 工具链仍为 HydraServe
  必需，保留复用。模型、LoRA、trace、源码及用户修改均不清理。

初次六目录盘点返回 1：两个项目私有容器层的 apt `partial` 子目录不可读。
权限缺口明确保留，不提升权限、不改容器目录权限，不把初次盘点称为全盘
完整扫描。随后对两个目标实验子树的详细元数据盘点返回 0。
父目录包括子目录，以上容量不得相加。

## 使用归档与恢复

历史证据路径不追改。需要读原始内容时，可流式读取相邻 `.gz`，或在有足够
空间时恢复原文件名。恢复前确认目标不存在，使用 `gzip -dk -- <archive>`
（不加 `--force`），然后核对回执 `source_sha256`；保留压缩副本和回执。
不要把压缩文件软链接成 `.json`，也不要用摘要文件冒充原始内容。
