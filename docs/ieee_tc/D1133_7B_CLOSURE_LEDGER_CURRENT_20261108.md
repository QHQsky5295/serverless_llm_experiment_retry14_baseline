# D1133：7B 当前闭口台账与主线转段判断

日期：2026-11-08。本文是对已经封存结果的离线复核，不启动 GPU、不修改
输入、服务代码、冻结指标或历史结果。它区分“运行已完成”和“论文主张已被
支持”，避免因为某个辅助指标退化而无限优化，也避免用单个有利指标宣称全面
优越。

## 1. 闭口规则

本台账使用冻结的 G1/G2 定义：

- 共同最低服务要求：冻结 TTFT/TPOT 阈值下，联合达成率至少 95%。
- G1：满足共同要求时，比较物理生命周期 GPU-s/request。
- G2：同一资源预算内，比较 P95 TTFT，同时单独报告联合达成率。
- CE、平均延迟、吞吐和价格只作解释或敏感性分析，不能替代 G1/G2。

外部系统低于 95% 时保留完整结果并标注“当前工作点未观测到共同要求可行”，
不删除该行，也不把它改写成系统不可能达标。单轮结果不计算运行间置信区间，
`n_correct=null` 继续表示没有独立数值正确性证明。

## 3. 7B 消融闭口状态

| 变体/证据 | 当前能支持的结论 | 不能支持的结论 |
|---|---|---|
| ElasticOnly → RoutingOnly | RoutingOnly 少用约 15.98% GPU-s，但联合 SLO 下降、P95 TTFT 变差 | 不能称 routing 单项全面改善 |
| RoutingOnly → RoutingHandoff (D1131) | handoff 产生了真实 movement/加载事件 | 不能称 handoff 单项降低尾延迟；本点反而增加 GPU-s 和 P95 |
| CapacityOnly → Full | Full 少用约 4.61% GPU-s，联合 SLO 增加约 0.30 pp，P95 基本持平 | 不能称 Full 每一步均单调改善或全局最优 |
| NoHandoff/R0H0/DelayedHandoff | 提供自然闭环下的资源—质量取舍和机制触发边界 | 不能把自然计划差异写成同计划因果收益 |
| NoHOST/FixedFull/NoRouting/ElasticLocality | 已完成单轮机制观测，字段和资源账目可追溯 | 不能以内部变体冒充外部论文 baseline |
| LastKnown (D1122) | 信息视图确实改变了少量路由选择和资源/质量结果 | 尚未隔离“confirmed tier propagation”唯一因果来源 |

这组消融已经完成执行闭口，但贡献闭口仍需按计划中的严格机制证据解释。
不能为了让 Full 与每个消融拉开预设百分比而修改消融实现、增加非目标等待、
清缓存或重排结果；如果差异很小，应如实写成有限或未分辨的机制收益。

## 6. 当前主线转段

本台账支持以下顺序判断：

1. 7B PrimeLoRA 自优化阶段：执行闭口，已有 W0/W1/W2 及预算工作点，不再盲目
   重跑 Full。
2. 7B published-baseline 合同复核：优先 ServerlessLLM，随后 vLLM、S-LoRA、
   Loquetier、HydraServe；复用有效结果，只有合同缺失才建立新执行键。
3. 完成同合同 G1/G2 表后，若 PrimeLoRA 在已测域不是最优，才依据具体资源—
   质量瓶颈登记一次针对性优化；不能通过筛选、削弱 baseline 或改变阈值取得
   排名。
4. 7B 核心机制证据和敏感性完成后，再进入 3B；不在 7B/3B 之间无界轮换。
