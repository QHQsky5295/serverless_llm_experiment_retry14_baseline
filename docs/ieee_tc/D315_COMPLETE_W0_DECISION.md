## 仍未解决的等待与资源问题

当前平均到达至准入为 681.229 ms，占平均 TTFT 的 52.226%。严格可加和分解：

| 区间 | 平均/ms |
|---|---:|
| 计划到达至服务端释放请求 | 187.154 |
| 服务端释放至全局准入入口 | 28.901 |
| 全局入口至受保护 runtime slot | 465.175 |
| 总和 | 681.229 |

routing 平均 177.688 ms 内嵌于上述区间，不能再相加。最终视图带权威读取的
3027 条请求，其 routing 平均 232.216 ms；其余 973 条为 8.051 ms。
这些条件组并非随机对照，也不是全部重试或 RPC 的准确总量，不能把组间差值
直接当作取消权威检查后的收益。下一步先定位真实串行依赖和等待所有者，
不能直接关闭 confirmed-state 检查、放宽可行性或取消原子 pin。

GPU-s 四个互斥时间窗为：业务前 37.759206、到达窗 15764.443673、drain
8.105349、终态后释放 55.309260；加和为 15865.617487。
**99.362% 的持卡时间在业务到达窗口内**，继续雕琢收尾不能解决主要资源目标。

1877 次控制观察中，发生 3 次 scale-up、0 次 scale-down；917 次观察中 queue
和 active 条件均低，但 TTFT 条件单独阻止 all-low；连续 sampled all-low
最长 35.197 秒，小于冻结 38 秒 cooldown。这只是实际控制轨迹，不是反事实：
不能据此把 38 改成 35，或扩大 TTFT 阈值来获得更好结果。

## 决定与下一主线

保留当前正确性修正及既有 1024 工作点作为后续开发起点，**不称它已整体优于
旧系统**。本预算候选的完整验证到此结束，不重跑同配置挑选更好结果、不新增
预算扫描，不重开已结束的 D295/PEFT 诊断。

下一问题是 7B 业务内的到达至准入等待及其对扩缩容、持卡时间的影响。
先对照历史测量和实现，定位可证伪的执行依赖，再结合官方实现提出单一候选；
保持 IEEE 公式、权威状态/所有权、原子 reservation、共同生成与评价协议。
不能通过放宽服务阈值或删掉合法远程开销代替优化。
7B 的旧 Prime 新指标对照、最终数值/warm/Resident 资格继续开放；之后才是
3B，再到基线、主比较、消融和敏感性。当前不跨阶段、不画图。
