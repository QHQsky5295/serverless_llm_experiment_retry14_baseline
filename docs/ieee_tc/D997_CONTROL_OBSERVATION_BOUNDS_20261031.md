# D997：控制反馈的有界复核，不再追加控制器候选

2026-10-31。上一轮D996完成完整负结果分析及备份，为实质进展。本轮继续
3B W2未达标主线，复用D992/D995的4000请求和全部控制日志，无GPU回放、
远端操作、生产算法/配置/九公式修改，无新工件/负载或图表。

## 问题与方法

D995提前准备使实际扩缩容从4/3变为8/7。本轮检验两个具体猜测：是否存在
高压力时反而缩容；完成数/忙实例秒的采样误差是否足以支持立即改控制器。

当前忙实例时间以控制采样时的active状态作左端矩形积分。离线从每请求
confirmed admission至原生末token建立区间，按native owner取并集；在
副本撤出路由时截断，因线上get_runtime_groups也排除draining owner。
这些区间在当前TP=1运行中属于真实请求占有的子集，但不包含准入确认前的
预留和末token后的清理，所以仅是忙实例时间**下界**，不冒称精确真值。
按原每个控制窗口裁切；原始采样分母与下界比较，不重放另一策略、不推造
反事实SLO。窗口重叠，不能视为独立重复。

## 裁决与历史排除

1. 当前两条完整轨迹均没有“score>1仍缩容”。不为未观察到的分支叠加新控制
   补丁；这不是证明该实现所有可能输入都没有优先级问题。
2. 采样确非精确积分，但D992大幅低估窗口仅10个，三个实际回收点也未出现
   D995那样的明显低估。当前证据不足以把事件积分当作修复D992剩余122条
   缺口的主要方案；不再为此启动一轮GPU试验。
3. D995继续不采纳，D992保留91.95%参照；95%目标、原n_correct未知、开发
   身份和完整G1/G2条件不变。没有以两边际都高于95%代替联合达成。
4. 再次核对D838/D839/D840：ISA-L组件加速是真实历史，但完整联合只增加
   1条，未解决目标。D992入口未启用该overlay，D995实际回执也为stdlib；
   这不是本轮新发现的因果收益，不重开解码器/线程扫描。D958已完成独立
   文件进程诊断，不能称为尚未实现的优化，亦不混淆不同执行环境。
5. D721–D724已排除“全部短输出违约均由prefill造成”，并已启用chunked
   prefill及扩展图捕获；不能再次包装这些开关为新候选。下一只读问题是
   当前多请求混合执行是否存在尚未覆盖的形状/时间边界。先复用D725的
   423请求并发profile和现有原生时间戳，不直接降低并发或扫描token预算；
   若缺具体观察量，说明缺口后才决定一次有界原生诊断，不重跑Full前缀。

### 混合形状的追加只读排除

已进一步按当前原生scheduler记录的同owner、同SCHEDULED时间分组（安装版
scheduler.py在同轮使用一个scheduled_timestamp）。D992有3876组，其中
116组同时接纳多请求，94组的完整prompt token和超过现有1024图捕获上限，
涉及196请求，最大2280。D995对应3871/113/98/212/2913。**完整prompt和
不是实际该步token数**，剩余预算与分块可能改变形状，不能据此宣布未捕获。

D992有133请求的decode包络与上述94组的prefill包络相交，排除自身并按
相同owner；其中21条TPOT违约，仅13条属于132条TPOT-only违约。因此，
即使存在大聚合形状，现有证据也不支持将其当作主要缺口或直接再扩图。
该只读补充未启动新性能实验；首次临时计数命令有括号语法错误，纠正后
直接重读原CSV，未产生或覆盖文件。后续须区分单次prefill、控制调用和
真正模型step，不以这些包络计数替代实际迭代成本，更不开始图大小扫描。

## 官方依据及适用限制

- [Knative原生请求统计](https://raw.githubusercontent.com/knative/networking/main/pkg/http/stats/request.go)
  在请求进入/退出事件处积算并发时间，支持区分事件积分和瞬时采样；它不是
  本项目忙runtime定义，也不证明更换观测后会提高SLO。
- [Chiron原论文](https://arxiv.org/html/2501.08090v1)将批处理能力、延迟和
  全局扩缩容关联，支持分开审视局部服务和全局资源控制；不照搬其工作负载、
  指标或收益数字。
- [vLLM 0.30优化说明](https://docs.vllm.ai/en/v0.30.0/configuration/optimization/)
  明确prefill预算与ITL/TTFT的取舍，不提供本机最优常数。
- [ISA-L 1.8.0源码](https://raw.githubusercontent.com/pycompression/python-isal/v1.8.0/src/isal/igzip.py)
  确认兼容单线程读器，与D838/D839既有解释相符；本轮未重新安装或运行组件。
