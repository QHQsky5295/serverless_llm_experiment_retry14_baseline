# PrimeLoRA 与 HydraServe 的指标体系对照

日期：2026-09-28。性质：用户新增问题的文献核查与理论分析，不是实验结果，
不修改正在运行的 D90 配置、IEEE 九式、正式 SLO 或已批准矩阵。
本分析采用 scientific-critical-thinking 的“观测—推论—待验证主张”区分。

## 结论

可以采用 HydraServe 的“服务要求达成率＋原始延迟＋资源代价”思路；
不应直接用它的全部数值或资源模型替换 PrimeLoRA 的协议。
现有计划已部分对齐，并增加联合 SLO 和物理 GPU 生命周期约束。
建议保留 G1/G2，明确展示 TTFT 边际达成率、TPOT 达成率和联合达成率。
CE 留作补充，不恢复为唯一优化目标。

## 推荐保留的精确定义

对全部 offered 请求定义正确完成指示 z_r；失败不从达成率分母删除。
TTFT 从计划到达到首 token，TPOT=(末 token−首 token)/(输出 token 数−1)。
客户端提交迟到不从用户时延中减去；一个输出 token 的 TPOT 为不适用。

令 T_r、P_r 为两个要求的达标指示；单 token 的联合判定只要求 T_r。

\[
A_T=\frac{1}{N}\sum_r z_r T_r,\qquad
A_{joint}=\frac{1}{N}\sum_r z_r T_r P_r.
\]

TPOT 条件达成率另在正确完成且至少两个输出 token 的集合报告，公开分母；
并列失败数和联合值，不把条件达成率当全部 offered 的可用性。
两个边际各 95% 不保证交集 95%；联合值不取两者平均、乘积或较小值。

\[
U=\sum_d\int 1\{\text{服务实际持有物理 GPU }d\}\,dt,
\qquad R=U/N_{correct}.
\]

同卡多个进程取占用区间并集；启动、准备、推理重叠不重复相加。
G1 仅在全部正确且联合要求达标的点比较 R；未达标点照常展示，但不列入
“满足要求后的最低资源”排名。G2 保留相同预算和服务要求约束下的 P95 TTFT。
另展示 goodput=N_good/T_observation 与 N_good/U，二者不是同一个量。
后一比值不是吞吐/美元；缺少服务要求时，单纯比值可能掩盖不可接受的失败。

## 为什么这比 CE 更贴近 PrimeLoRA

1. **减少错配和远端 miss：**同一次请求的真实等待下降，可提高 A_T，降低
   TTFT 尾部；只有改变实际关键路径才形成收益，累计搬运时间不能直接减 E2E。
2. **扩容 handoff：**准备与初始化重叠，可能降低 activation 后的 first-service
   TTFT；若提前持卡过久，U 可能反而增加，需要同时检验。
3. **层级驻留：**复用 HOST/NVMe/GPU 可减少重复获取；代价是驻留空间、管理
   和可能的替换开销。单报 hit rate 不是最终优势，须观察服务与资源结果。
4. **admission：**准备干扰减少可能改善 TPOT；但延后加载也可能恶化下一请求
   TTFT。联合要求和后续请求观察可以阻止“推迟工作就是优化”的错误解释。
5. **弹性回收：**相对常驻系统可能以相近达成率使用更少 GPU 时间；相对其他
   弹性系统则需在相同预算下证明更好的服务结果。无需假设所有原始延迟都胜出。

这是一条机制到指标的可证伪推论，不是当前数据已证明 Prime 领先。
若两个系统 A_T 都接近 100%，该指标会饱和，GPU-s 和尾延迟仍能分辨差异；
若只改善极少数请求，整体 P95 也可能不动，需以预定义 activation/first-service
分组展示，不事后筛“有利请求”。

CE=1/(LC) 允许价格和平均时延相互补偿，不能回答是否达到共同服务要求；
改为上述体系不是保证胜出的技巧，而是直接检验论文要解决的问题。

## 为什么不直接换成 GPU memory-time 成本

设内存资源占用 J=Σ_d∫m_d(t)dt，单位 GiB-s。它与 U 的关系取决于分配模式：

- 同构整卡独占、每卡容量 M、以保留容量计量时 J=M×U，排名相同。
- 以实际已用显存计量时，两者一般不等价；只用一半显存但整卡不可给其他任务，
  不意味着释放了半张卡。vLLM 的 KV 预分配也会改变该数值。
- 真正可强制共享、可核验资源归属的环境下，memory-time 有独立用途，但不能
  将共享环境的计费假设直接套给当前整卡持有模式。

因此物理 GPU-s 保持主资源指标；GiB-s 可在已有可核验遥测基础上补充，明确
allocated/reserved/used 含义，不把未知的短时间占用插值称为精确计费。
CPU、HOST 和远端开销另外报告，GPU-only 数值不冒称完整云成本。

## 本轮新增优化授权的执行解释

用户允许在保持论文行间公式和核心思想时，自适应优化其他机制和底层实现。
继续优先以可观测量驱动：实际完成/排队、native KV 和 slot、传输字节与耗时、
真实占用、完成事件和已知启动成本；每轮核对相关论文/官方源码与历史失败。
禁止用未来 workload、测试点名称、结果胜负切换规则。

不能把新的手工系数包装成“自适应公式”；保留不可消除的物理上限、安全阈值
和公开实验常量。对不可观测量明确假设，验证收益与副作用后才接受。
不同模型可有来源明确、验证后冻结的配置；正式点不单独调参。
当前在运行的 D90 不改动；后续优化仍按完整实现→比较→归因→验证的主线。
