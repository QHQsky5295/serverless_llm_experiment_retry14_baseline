## 时延结果与研究解释

以下为同一个完整运行的描述性结果，n=1 run；每列请求样本数均为 4,000。
P95 使用冻结协议的 Type-1 分位数，不给单次运行伪造 CI。

| 指标 | 平均值 | P95 | 单位 |
|---|---:|---:|---|
| 请求 TTFT | 122.146518 | 268.605684 | s |
| 控制器内部完成 E2E | 127.878409 | 276.160061 | s |
| 外层内部终态时延 | 130.181999 | 278.812444 | s |
| dispatch/admission 前等待 | 114.177866 | 256.284624 | s |
| └ dispatch window 等待 | 99.994035 | 237.228618 | s |
| └ runtime slot 等待 | 11.679442 | 33.205326 | s |
| └ 到达释放迟到 | 2.504390 | 11.169422 | s |
| service TTFT | 7.968652 | 40.182378 | s |
| └ admission 至 native dispatch | 7.493005 | 39.763939 | s |
| └ native vLLM TTFT | 0.475647 | 1.421746 | s |
| native decode | 2.955939 | 7.923488 | s |
| worker 完成通知 | 0.047142 | 0.101941 | s |

| controller 至外层终态 | 2.303560 | 7.041737 | s |
| TPOT | 29.955123 | 64.782991 | ms |

观察：平均 TTFT 主要由 dispatch 前等待构成，而不是 native vLLM 的首 token 计算。
含 adapter 获取/准备的 service 路径也存在尾部，不能把 service TTFT 当作用户 TTFT。
这支持继续检查控制和准备路径对有效服务容量的影响，但不是对某个子机制的因果证明。
完整回放和正常收尾解决的是执行可靠性，不证明 G1/G2 优越性。

嵌套项不能重复相加，P95 不能相加。`lora_io_ms` 平均 6.408645 s、P95 38.231640 s，
是嵌套诊断，不额外加入上表总时延。两个旧 parent pickup/thread-resume 字段没有样本，
保留 n=0/N/A，不补零。外层终态位于 reservation/global admission 释放之后；
Unix 回放通道没有响应回传，因此 controller 与 outer 两种内部事件都不是客户端收包时间。
保留原始定义，正式 E2E 的完成边界核对仍见 D115_COMPLETION_BOUNDARY_SOURCE_AUDIT.md。
