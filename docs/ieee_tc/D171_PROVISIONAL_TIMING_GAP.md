# D171：7B Full 对候选共同门槛的时延缺口

日期：2026-10-02。开发诊断，不是正式 G1/G2 结果。

## 问题、来源与限制

复用 D164 的 7B Full W0、4,000 请求完整运行和已保留的 34 MB 请求投影，
采用 D170 实测的 7B warm 候选门槛。不重新运行 GPU、不生成工件/负载、
不重新解析巨大原始日志、不修改服务代码或已封存结果。

| 原生输入长度 | 请求数 | TTFT 候选门槛（秒） | TPOT 候选门槛（毫秒） |
|---|---:|---:|---:|
| ≤616 | 1,039 | 2.990092 | 59.646198 |
| >616 | 2,961 | 4.635325 | 85.345274 |

计算使用未舍入的秒值，等于门槛通过。候选门槛分别为 warm 均值的 5 倍和
2 倍。3B 的共同 batch 条件尚未验证，故共同参考没有全局冻结；不得把本表
改名为正式达标表。原生 token 数、时间线、身份字段完整，不等于数值上的
adapter 执行正确性已经证明。`N_correct` 仍为未知。

令 J 为只按时延判断同时通过的请求数，则在这些候选门槛下：

`A_joint ≤ J / N_plan`。

这是因为正确性指示不可能大于 1，并非假定所有请求正确。正式联合达成率、
GPU-s/correct-request、Resident 预算仍为 N/A。单 token 的 TPOT 必须 N/A，
已知失败先计不通过；缺失成功请求的必需字段直接拒绝分析，不能删除该请求。

## 结果：当前候选系统仍有明确性能缺口

| 互斥类别 | 请求数 | 占全部 4,000 请求 |
|---|---:|---:|
| 两项时延均通过 | 2,110 | 52.750% |
| 仅 TTFT 超限 | 1,660 | 41.500% |
| 仅 TPOT 超限 | 91 | 2.275% |
| 两项均超限 | 139 | 3.475% |
| 观察到的失败终态 | 0 | 0% |

TTFT 时延侧通过率 55.025%；TPOT 条件时延通过率 94.250%，条件分母为
4,000 个多 token 请求。两者不能相乘或取最小值冒充联合值。
联合上限为 **52.75%**，距 95% 差 **42.25 个百分点**，至少还需要
**1,690 个请求**从时延不通过变为通过。即使以后完整证明执行正确性，
也不会自动消除这个时延缺口；但这些值仍不能代替全局冻结后的正式判定。

## 观察到的阶段分解

各项来自同一可靠时间域，逐请求可加和，不把重叠活动相加。

| 到首 token 的阶段 | 全部请求平均（秒） |
|---|---:|
| 计划到达→控制器准入 | 2.850748 |
| 控制器准入→引擎 dispatch | 1.386105 |
| 引擎入口→原生队列 | 0.144657 |
| 原生队列等待 | 0.048456 |
| 原生 prefill | 0.236057 |
| 总 TTFT | 4.666023 |

前两段合计占平均 TTFT 的 **90.80%**。1,799 个请求 TTFT 超限，其中
**1,547 个在进入引擎前就已耗尽首 token 时限**。这定位了必须解决的时间
区间，但不代表这些时间全是“无效控制开销”：其中包含真实容量等待、准备、
传输及执行接口开销。不能直接减掉这些时间宣称某个优化的反事实收益。

| dispatch 前确认 tier | 请求数 | 两项时延通过数/比例 | 平均 TTFT（秒） | 准入前/后引擎前平均（秒） |
|---|---:|---:|---:|---:|
| GPU | 1,361 | 927 / 68.11% | 3.449674 | 2.803033 / 0.187505 |
| HOST | 1,530 | 709 / 46.34% | 5.210093 | 2.777237 / 2.013863 |
| NVMe | 969 | 458 / 47.27% | 4.889450 | 2.952057 / 1.525224 |
| Remote | 140 | 16 / 11.43% | 8.998341 | 3.416782 / 5.214807 |

这些是系统实际形成的条件集合，不是随机化 tier 对照，不能据此声称 HOST
比 NVMe 慢的因果结论。即使 GPU-ready 组仍有明显准入前等待，说明不能仅靠
减少远程下载次数解释或解决当前全部问题。当前 Full 的原始 P95 TTFT
11.316414 秒、P95 TPOT 81.865101 毫秒也完整保留。

物理生命周期总量沿用 D164：15,929.859233 GPU-s；除以 offered 4,000 得
3.982465 GPU-s/offered-request，仅作诊断，不称 G1 合格资源成本。

## 结论和下一步（主线不变）

1. 目前不能关闭 7B 优化：门槛候选、正确性及旧 Prime 的新指标对照仍未闭合，
   且已有足够证据表明时延优化不可省略。
2. 下一候选优先针对准入前等待与 HOST/引擎前准备的实际实现原因，结合
   D161/D162 的既有诊断和官方实现核查；一次只验证一个可证伪假设。
   D163/D164 的小幅结构优化没有带来已证实的完整回放收益，不作为达标证据。
3. 不凭本次结果扩大 batch、放松门槛、改变 SLO 公式或给远端传输免计时。
4. 磁盘仍略低于 150 GiB 新重型任务门槛。下一 GPU 实验前只回收已审计的
   可重建资源或做校验后的无损归档；不删除唯一测量和工件，不降低门槛。
5. 7B 按新 G1/G2 相对旧 Prime 达到目标后再进入 3B 优化，随后才恢复外部
   baseline、主比较、消融和敏感性。不能跳过这些尚未完成的任务。
