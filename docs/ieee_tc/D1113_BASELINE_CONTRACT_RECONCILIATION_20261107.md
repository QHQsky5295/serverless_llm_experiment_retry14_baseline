## 1. 具体裁决

| 系统 | 近期运行 | 对当前主比较的分类 | 复用的既有 W2 |
|---|---|---|---|
| ServerlessLLM | D1103 | R2：诊断，不能直接进入当前时延或资源主表 | D555 |
| vLLM | D1106 | R2：诊断，不是共同 0.30.0 后端参照 | D557 |
| S-LoRA | D1108 | R2：诊断，不是共同资源包络的比较点 | D591 |

本次逐请求证据排除了一个先前待核查的疑点：三条近期运行与 D1100 的
4,000 个 canonical prompt hash、adapter ID、target token 数全部相同。
因此不能把问题归咎于 prompt/目标工作量不一致，也不需要重建输入。
真正不能混合的部分如下：

- 三条近期 replay 均记录 `replay_time_origin=process_start`，没有与共同
  deployment notice + 60 s 绑定。vLLM/S-LoRA runner 先等待副本 ready，
  再开始 replay；其已记录启动时间显著超过 60 s。ServerlessLLM runner
  也是在 stack/deploy/可选等待之后另起 replay，没有共同绝对到达时刻。
  这不能通过事后减/加启动耗时或平移请求时间补成真实闭环执行。
- 它们的 TPOT 定义使用 service completion，而非末个原生 token。与相同
  完成边界重算为零误差，只能证明内部恒等，不证明符合冻结 V1。
- 汇总成本明确为 `simulated_gpu_second_deployment_lifecycle_v3_capped`，
  含 300 s idle tail。该逻辑计费不等于实际物理 owner 区间并集。
- 5,000 ms TTFT-only 不是 D394 分长度组的联合 TTFT/TPOT 事件。D1108
  的“joint TTFT SLO 100%”标签撤回；不能以该字段证明联合达标。
- D1106 使用 vLLM 0.10.2，不是 PrimeLoRA 的共同 0.30.0 参照。
- D1108 回执报告 95/100 GiB high/max，区别于共同 72/80 GiB；不能因为
  “未 OOM”将改变后的包络写成同合同。其约 102 GiB 的旧文字也不作为新的
  实测结论，本次没有据此推断实际内核限额或内存峰值。

这些是执行条件/定义差异，不是三种系统的机制优劣结论。成功完成和原生
token 数仍有诊断价值；不会删除表现好或差的记录。已有可比数据足够覆盖
这三个 W2 键，故不再各重跑一轮，也不对旧 runner 作无必要的性能改造。

## 3. 当前可比 W2 观察（不是最终正确性或最优性声明）

| 系统/运行 | 联合 SLO | 物理 GPU-s / offered request | Type-1 P95 TTFT ms |
|---|---:|---:|---:|
| PrimeLoRA D1100 | 98.050% | 2.628999 | 2815.059 |
| ServerlessLLM D555 | 93.900% | 3.973411 | 9516.719 |
| vLLM D557 | 98.225% | 4.028890 | 1751.295 |
| S-LoRA D591 | 91.050% | 3.695866 | 151375.834 |

各点全部 4,000 请求具有完整原生绑定/计量；`n_correct=null` 保持原样。
分母明确为 offered request，不能改称已独立证明的数值正确请求。
固定 seed42 已知回放属于开发期单轮观察，不是独立留出，不计算 CI。

PrimeLoRA 相对达标的 vLLM 观察点少用 **34.746%** GPU 时间，但 P95 TTFT
高 **60.742%**，联合达成少 **0.175 个百分点**。可表述为明确的资源—时延
取舍，不能写成所有原始指标都更好。
D594 已冻结 W2 预算为 12,086.669344 GPU-s，D1100 的 10,515.996271 GPU-s
在预算内。vLLM 常驻观察点超过该预算；这不证明 vLLM 所有预算内配置不可行，
也不能由此宣布同预算尾延迟全面支配。仍须完成既定 M1/M2 范围。

原生输出 digest 与 D1100 不同的请求：D555 170、D557 175、D591 173。
跨后端本就不要求 bitwise 相同；D557 同后端差异也明确保留，不能无证据地
全归为舍入。此次确认的是同输入/adapter 内容/原生计量，不是独立数值输出
证明。该局限不触发重建工件池，也不阻塞其余计划实验。
OS/page-cache、编译历史或远端全程无干扰未由输入匹配得到证明。
