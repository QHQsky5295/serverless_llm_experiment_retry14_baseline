## 核验范围

复用现有 analyzer 的原生绑定和时序检查，逐条验证原始 trace 的 request ID、
adapter、目标 token、source-item SHA、到达时刻；保存完整输入向量 SHA。
十项原生 source/owner/lease/slot/内容/释放检查均为 4000/4000。
TTFT、TPOT、E2E 从同一单调时钟重新计算，最大误差均 0 ms。
物理区间积分、互斥窗口之和、12 个 allocation journal SHA 和终态账本一致，
无开放租约。4031 个监控采样中，本轮 service high/max/OOM/swap 均为零。

这不是独立 kernel 数值正确性证明。沿用 D393 对冻结 V1 的解释：不要求跨
后端逐 token 完全相同；独立数值诊断仍保留。既有工件池主要是零 LoRA 更新，
只能支持结构性多 adapter 服务工作负载，不能宣称 500 个独立训练任务或质量结论。

## 两个历史标签的纠正

- 实际存在 132 次远端已发布 gzip 传输，线上字节 131480060，无请求时打包。
  `local_sim_no_delay` 是未启用 sleep 限速器的旧汇总标签，不能据此称 D371 没有
  真实远程传输。原始标签保留，以请求/服务端交付证据解释，不篡改旧 JSON。
- `time_scale=8` 属于既有源 trace 的生成身份。实际外置回放 `rate_scale=1.0`，
  W0 源 trace SHA 和到达映射逐条一致，不是本次又额外压缩八倍。

请求内可匹配 131 个远端 transfer ID，而服务端为 132；一个未匹配的请求级
细分记录保留为字段完整性限制。它不影响用户原生时延和整体线上字节，但不能
宣称远端阶段逐请求归因 100% 完整，后续阶段分解不得补造该记录。
