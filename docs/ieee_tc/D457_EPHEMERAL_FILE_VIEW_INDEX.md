# D457：单次新鲜文件视图的路径索引优化

2026-10-12，开发候选，尚无新 GPU 性能结果。承接 D454–D456，不重复诊断回放。
主线仍是 7B PrimeLoRA 优化；评价使用冻结 V1／单轮 V2，未改变共同阈值。

## 证据与可证伪假设

D456 控制器的 538 个业务期样本中，90 个包含 preparation_snapshot，43 个
包含来源观察、17 个包含替换容量；计数重叠，不能当作 CPU 时间比例。
具体栈显示 Path.parents、relative_to 和重复 Path 构造。D455 同时显示控制器
到达/完成处理延后，但没有证明文件视图是全部延迟的原因。

历史 D93 修正源/容量版本一致性；2f1bc4b 将替换容量按 inode 索引；D153
合并同次库存扫描；D188/189 分离不可变工件描述；D193/194 精简原生视图。
这些改动保留，不再声称本轮首次消除逐候选扫描或首次异步化纯 planner。

假设：在相同新鲜库存上，利用已有 path_tiers 和规范路径，以及按路径组件
而非逐级 Path 对象做祖先交集，可减少同步 Python 对象工作，且输出逐字段相同。
只优化这两个投影函数；不改库存遍历、两次 lstat、锁、epoch、预留或执行重检。
不引入 TTL、跨调用动态缓存、未知状态默认命中、线程兜底或阈值放宽。

## 原始资料及适用边界

- [vLLM 官方 CPU 性能分析](https://vllm.ai/blog/2024-09-05-perf-update)
  指出 Python 对象管理和同步服务组件会产生开销。只借鉴减少已观测冗余工作
  的方法，不移植其策略，也不借用其加速数字。
- [Python 3.12 pathlib 文档](https://docs.python.org/3.12/library/pathlib.html)
  明确 parts、parents 的词法语义；比较完整组件，不能用不带分隔符的字符串
  前缀判断祖先。绝对根、相似前缀、同名跨 tier、嵌套源及硬链接必须覆盖。

## 实现边界与验证顺序

1. 来源投影仅消费本次双重检查成功后导出的 stat 与 path_tiers；直接子树和
   相对子路径只在本次调用内索引。层级标签/路径不一致显式拒绝。
2. 替换容量保持所有硬链接必须位于目标树内、同设备、无外部链接/未结算增长，
   以及 held/moving/planned 阻止替换。祖先交集不改变可回收字节定义。
3. 复用已有小文件测试，补嵌套/跨 tier 别名、路径前缀和对象构造边界；用父版本
   两函数 AST 作独立逐字段对照。两次 stat 与变更拒绝必须仍然通过。
4. 复用 D153 组件研究方法，在既有 fixture 上做交替组件计时和工作量计数；
   不生成 LoRA/trace，不将微测换算成 TTFT/GPU-s，不作运行间 CI。
5. CPU 资格和备份后，登记一个受影响的原始 1000 请求最小验证，再用普通
   4000 W0 完整评估；保持 D371 cap14/profile、60 秒准备和真实只读远端。
   不用 D456 带观察器的诊断结果作为无观察器性能基线；保留所有退化/失败。

CPU 分析仅使用既有 3/4 GiB、swap0、CPU2,3,26,27 域；GPU 性能期间不分析、
清理或维护远端。旧147项、用户文件、协议和历史运行不覆盖。
尚未完成：本候选验证、7B W1/W2/G2、3B、其余基线资格及全部消融/敏感性。
