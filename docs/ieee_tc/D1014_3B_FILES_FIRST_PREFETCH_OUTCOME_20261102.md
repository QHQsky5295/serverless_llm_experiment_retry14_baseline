# D1014：减少辅助查询的完整回放结果

## 结论与当前主线

**本候选拒绝替换 D1000。** D1014 完成一次 3B W2、4000 请求回放，终态失败为0，
原生生成、内容/adapter绑定、计时重算和物理GPU释放审计通过，但联合SLO下降，
GPU时间基本不变。机制确实触发，不等于服务性能改善。保留全部结果，不重跑同键，
不放宽共同阈值；D1000仍是开发参考且仍未满足95%的联合要求。

这是已知source42工作负载上的单轮开发观察，不是独立留出、显著性或最终G1/G2
胜出证明。独立全量数值正确性仍为未知，`n_correct=null`；4000次正常终态和
native-contract完成不能改写成另一个未经证明的分母。

## 支持的解释与停止边界

减少了非必要完整查询，但**本轮没有观察到联合服务质量或有意义的资源收益**。
该结果不支持继续微调这个预检查顺序；不能仅因内部计数下降而接受性能退化。
单轮结果也不足以证明每一毫秒退化都由文件查询造成，或证明所有同类设计无效。

已有阶段分解显示全体4000请求中，最大TTFT分项为arrival-to-admission的有2604条，
admission-to-acquired的有979条；两者是记录的时间段，不分别等同纯CPU、网络或
缓存miss。之后的唯一新候选须由保留的阶段/原生事件提供新证据，并排除D995–
D1013已经无效的等待、容量、控制延后方向，不能盲目堆叠下一补丁。

不重新运行既有baseline资格或把低于95%的baseline从表中删除。最终同版本
W0/W1/W2比较、G1/G2、A1–A5、S1–S13、审稿文档和图表仍未完成；本轮只关闭
一个开发假设，完整目标保持进行中。接近目标前不作展示图。
