## 2. G1 判断

按冻结的 G1 顺序，先要求共同工作负载完成并达到联合 SLO≥95%，再比较物理
lifecycle GPU-s/request。

在这组已封存的 W1 工作点中，PrimeLoRA 是唯一达到 95% 联合要求的系统。因此
目前可以写出一个有限结论：

> 在该固定 W1 工作点和当前已绑定的外部配置下，PrimeLoRA 达到了共同服务要求；
> 其余已测系统未达到同一联合时延要求，因此不能直接把它们作为“同质量资源效率”
> 的可行对照点。

这不是“PrimeLoRA 在所有配置下全面优于所有系统”的证明。对低于 95% 的系统，
应保留其 SLO、GPU-s 和 P95 TTFT，用于完整资源—质量边界，而不能在 G1 分母中
强行填入不可行点。

## 3. G2 判断

当前 7B W1 的 PrimeLoRA 物理 GPU-s 为 7603.875，高于已登记的约 6756.571
GPU-s 参考预算。因此这张表还不能支持 G2（共同预算内的 P95 TTFT 与联合 SLO）
闭口；不能通过修改预算或从现有点插值制造一个三卡工作点。

当前最诚实的论文表述是：

- G1：该 W1 工作点支持“满足共同服务要求的可行性”以及相对于低质量点的
  资源—质量优势，但不构成所有系统同质量资源效率的完整证明；
- G2：尚缺少满足共同预算的 PrimeLoRA 工作点，不能声称预算约束下的尾延迟优势；
- 辅助结果：PrimeLoRA 的 P95 TTFT 明显低于五个已测外部系统，但这部分比较必须
  同时报告各系统联合 SLO，不能只展示 P95。

## 4. 这张表如何改变下一步

这张表说明 7B 已经不需要继续重复同一个 Full 或 A2 capture。下一项有明确科学
问题的工作应当围绕 G2：在不改变共同 workload、生成契约或论文公式的前提下，
获得一个预先登记且可解释的资源工作点，或根据已有配置明确说明为什么该预算点
不可达。之后再决定是否需要一次有证据支持的 PrimeLoRA 优化。

在 G2 之前，不应把 W1 的 98.55% SLO 当成系统全面最优；在 G2 之后，也必须同时
检查 P95 TTFT 和联合达成率，不能用 GPU-s 降低抵消尾延迟或质量退化。

## 5. 与 A2 capture 的边界

d1150/d1158 不属于本表。它们冻结的是 handoff 计划和扩缩容提交前沿，目的是验证
受控回放，而不是提供新的主系统资源工作点。把 d1158 的 9674 GPU-s 放入本表会
混淆机制控制实验与主性能实验，因此明确排除。
