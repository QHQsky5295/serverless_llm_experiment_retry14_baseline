## 证据、历史与可证伪假设

D603后半程到达/完成通知延迟增大，控制器库存遍历采样增多；这不是函数CPU
时间或因果贡献。D605的字符串遍历在需要导出stat映射的规划路径没有收益，
因为它重建了Path键。那个原型不采纳，本次不是重跑它寻找更好数字。

当前全仓caller审计发现，私有`_observed_stats`仅由inventory逐层转发，生产
只在preparation_snapshot消费一次；消费函数立即将其Path键转回字符串。
假设：让双重实时扫描和这一投影共用同一种规范字符串表示，可以消除这些
往返转换，降低同步控制工作；不缓存或少测任何动态物理事实。

保留D93来源/预算同epoch、D153同次合并扫描、D352同事务HOST复用、D365内容
与分配身份分离、D457投影索引。D329反例禁止owner/epoch替代动态物理观察；
D529和D598完整回放负结果表明组件改进不保证端到端收益，不能复活旧候选。

## 原始资料与实现边界

- [vLLM CPU开销分析](https://vllm.ai/blog/2024-09-05-perf-update)：减少已观测
  Python对象管理值得验证，不借用其加速数字或异步策略。
- [vLLM 0.30 worker管理](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/worker_manager.py)：
  单线程原生owner及加载验证/容量步骤不能由外部文件身份替代。
- [Python 3.12 os](https://docs.python.org/3.12/library/os.html#os.scandir)：
  DirEntry元数据会缓存；本候选仅枚举名称，仍两次显式调用
  `os.stat(..., follow_symlinks=False)`。
- [CPython 3.12 pathlib](https://raw.githubusercontent.com/python/cpython/v3.12.0/Lib/pathlib.py)：
  根仍以Path词法规范化；兄弟名称按相同次序排列，`.`子路径不添加`./`。
  只验证本机Linux语义，不声称Windows等价。

本轮联网复核上述官方文档和代码。生产仅改库存内部表示及唯一私有消费合同。
不改锁、epoch、容量、引用、执行重检、writer边界、未确认源拒绝、后端或配置。
不保留跨调用映射，不用TTL、重试、吞异常或unknown→ready；不改远端和评价尺子。
