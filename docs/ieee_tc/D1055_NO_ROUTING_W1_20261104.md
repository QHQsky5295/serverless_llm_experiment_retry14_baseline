## 问题、历史与原始资料

检验在相同 owner、可行集、分层驻留、handoff、admission 和弹性控制下，
将论文服务时间分桶排序替换成 live-load 排序，会怎样改变联合 SLO、尾部 TTFT
和物理 GPU 生命周期。不能预设 Full 最优，也不能由选择次数直接推断收益。

D1049 已指出旧 least_connections 会切离 IEEE ownership、activation 和计量
入口，不能用作同运行时单因素消融。D448 的 gpu_locality 实现证明可以只改变
owned snapshot 的 selector；但它使用二元 GPU 命中和 slack，也不是 NoRouting。
历史实现提交 ba9775e2be55ea67cf76ae96f1ee47fab821da15 保留。最近 pool 修改为
d66cf969409b33ce29118e25530c2d7250a46e82，本次不改变其来源预取行为。

2026-11-04 核查 [vLLM Router 官方说明](https://raw.githubusercontent.com/vllm-project/router/main/docs/load_balancing/README.md)：
power-of-two 以候选当前负载选择，cache-aware 则另考虑缓存。本实验借鉴的是
将负载与缓存信息分开的对照思想；不复制随机二选一，不冒称复现该系统。
[dLoRA 原论文](https://www.usenix.org/system/files/osdi24-wu-bingyang.pdf) §5 将请求负载与
adapter 位置联合处理。这说明负载排序不是新算法贡献，不能用 NoRouting
单项证明现有论文缺少所有协调能力。真正 confirmed/last-known 信息差异仍属 A3。

## 唯一排序差异及不变项

Full 在同一不可变快照的可行副本上按以下键排序：

`(floor((D+T+O)/delta), admitted_requests, pending_loads, gpu_utilization_pct, last_dispatch_at, replica_id)`。

NoRouting 仅去掉第一个 service-bin 项：

`(admitted_requests, pending_loads, gpu_utilization_pct, last_dispatch_at, replica_id)`。

它不读取 tier/D/T/O 来排序；保留完整 live Q 和相同稳定 tie-break。
无可行副本仍排队，不隐式选主实例。实际来源保护、原子容量预留、adapter
active-set 可行性、取消、释放、并发冲突重查全部走同一原生路径。

新接口是 `routing_policy=ieee_confirmed` 下显式的
`ieee_selection_strategy=load_only`。默认仍 service_bins；禁止将 load_only
挂到 legacy policy，也不接受 locality slack。选择尝试计入 load_only，
不误计为 readiness-aware。只读 shadow 调用不更新计数/owner。

runner 已将 selector 透传到 scale-up 路由投影，故实际和投影均用 load_only；
不把投影偷偷保留为 Full 排序。自然反馈可能改变计划、扩容和驻留内容，
这属于同控制规律下的结果，不能声称运行期间实际状态完全相同。
共同 profile/快照采集开销保留；本实验隔离决策规则，不是最小化观测成本实验。

生产文件只改 instance_pool.py：新增纯 selector，扩展显式枚举和调用分支/计数。
AST 核查仅 Router.__init__、Router.select_instance_with_decision 两个既有定义改变；
Full routing_key、select_ieee_snapshot、其余既有定义和整个 runner 未改。
不能将消融删去公式项解释为修改正式 Full 九个公式。
