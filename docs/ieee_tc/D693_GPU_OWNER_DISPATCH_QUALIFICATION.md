# D693：同副本最终 GPU 准备的执行资格

2026-10-18。这是3B PrimeLoRA主线上的单一候选验证，不是新的性能结果。
上一完整候选D688联合达成91.125%、15897.107082 GPU-s，其改动已撤回；
当前父版本的D682为92.350%、15896.253912 GPU-s，仍未满足共同95%要求。
不修改SLO、75%预算、九个公式、生成或工作负载；独立数值正确性仍未知。

## 1. 假设及依据

D692复用D684诊断日志，1512个有回执GPU准备尝试中474个因快照过期延后；
其中只有12个属于已GPU-ready复用。不能将准备注册当物理pin或跳过确认。
D692真实runner/native-owner CPU fixture进一步隔离出一条因果路径：两个
同owner目标并行时发生一次相互失效，3次观察/提交才完成；逐个执行则2次
完成同样的一次实际加载和一次GPU复用，租约与目标保护均释放。

本次再次核查[vLLM 0.30.0官方worker manager](https://raw.githubusercontent.com/vllm-project/vllm/v0.30.0/vllm/lora/worker_manager.py)
的`LRUCacheWorkerLoRAManager.add_adapter`：原生操作依赖单线程core loop。
由此结合本项目多次异步RPC观察得到的推断是：单个操作串行不保证整个
observe→prepare→release动作与另一个动作不会交错。并不借此宣称所有过期
都由兄弟任务造成，普通需求、HOST任务和注册时变化仍可使快照失效。

历史核查继续沿用D104/D134/D176的注册、物理引用及来源边界，D355/D691
已证明控制交错工作；D514查询替换与D687元数据表示的完整退化均保留且不重做。
没有把局部操作次数减少当成可直接扣除的E2E时间。

## 2. 唯一生产变化

只修改`faaslora/preloading/preloading_manager.py`的`OwnedMovementQueue._pump`：

- 根据当前执行动作，派发集合中每个native owner最多一个最终GPU动作。
- 同一owner的HOST/NVMe及其他owner的GPU仍可并行；全局并发配置保持3。
- 忙owner的待执行GPU任务不占全局slot；对当时可执行集合沿用demand、收益
  密度和稳定身份排序，不新增sleep、阈值或按模型/场景切换的策略。
- 前置远端/本地物化仍在最终GPU任务提交前执行，不占这个GPU执行资格。
- 完成、延后、失败、取消后的资格释放使用原有实际任务终态；取消收尾尚未
  结束时仍算执行中。没有释放未知物理租约或跳过失败恢复规则。
- 原生epoch、物理容量、planner/admission、准备目标、收益计算、事件唤醒、
  共享订阅和最终释放逻辑全部原样。不是将整个系统设为并发1。

候选生产文件SHA：
`f4415b48184f5fc6774f23fd526692cf50a771b20f6fd2a0f5ef893bf37a3cc4`。
父文件SHA：
`825ead7f23686b8f501dd8d833cfa27111cc55fbbfda1191bed6a25b1f48654f`。

这改变准备动作的可并行执行关系，不改变论文选择公式或普通请求的可行集。
代价可能是少量同owner准备无法重叠；是否净改善必须由实际回放验证。

## 3. 验证结果及失败保留

| 阶段 | 结果 | 解释 |
|---|---|---|
| 初次定向检查 | 43项通过 | 真实runner两目标仍2次完成，普通需求变化仍被拒绝 |
| 初次完整检查 | 714项，4个错误 | 1个旧测试要求同owner同时进入而超时；3个原生方法检查误用旧vLLM环境 |
| 中间检查 | 711项，1个失败 | 去掉旧并发屏障后，仍错误要求未开始的兄弟任务产生物理失败 |
| 最终相关回归 | 712项通过 | 包含1项明确隔离的历史并发收尾回归和新增串行行为检查 |
| vLLM 0.30.0原生方法检查 | 3项通过 | 使用现有新后端环境、CUDA不可见；不加载模型 |

最终共715项检查，初始43项是重叠覆盖，不累加为独立测试数。712项中一项
使用SHA核验的父版本`_pump`，专门保留“已执行兄弟任务取消失败不可隐藏”的
历史断言；只绑定该测试实例，不修改全局生产实现。另一个测试使用当前生产
顺序，验证未开始的兄弟任务被取消、计划以superseded结束且全部保护清空。
不能将历史用例冒称当前生产并发场景，也不能删除旧失败来让回归表看似全绿。

新增覆盖包括：同owner互斥但其他owner/HOST可用；deferred释放执行资格但
不自动重试；共享订阅的最后取消必须等待实际收尾；首次指令前取消释放资格；
失败键不被复活；普通需求仍能导致stale_snapshot且只能在真实wake后重新观察。
完整相关集合还覆盖混合远端→HOST→GPU、单slot前置依赖、跨计划共享、来源
增长/失效、主动替换、容量及请求生命周期。所有最初失败与准确源码版本保留。

没有新增推理路径测量代码。三个修改文件是生产queue与两份既有测试；复用
D663受限资格、D668关闭及D612明确路径发布入口，没有另建实验框架。
