## 阶段分解与下一问题

| 阶段 | D150 均值 (s/request) | D152 均值 (s/request) |
|---|---:|---:|
| 计划到达到入口放行 | 293.264045 | 95.252678 |
| 入口放行到所选源准入 | 1.433226 | 1.241048 |
| 所选源准入到原生 dispatch | 1.572029 | 1.147328 |
| 原生 dispatch 到末 token | 4.867887 | 4.345848 |
| 末 token 到 controller 完成 | 0.531472 | 0.575936 |
| controller 完成到外层终态 | 0.327878 | 0.293963 |
| 入口到外层终态上包络 | 8.732492 | 7.604123 |

dispatch/admission 平均等待 96.493726 秒，占平均 TTFT 的 98.501%；service
TTFT 为 1.468022 秒。入口至终态仍仅是许可占用上包络，不是精确 permit release；
内部 E2E 与外层终态也均不等于客户端接收。不能通过减掉排队或远端传输获得
“优化后 TTFT”。排队对非生成开销具有累积放大，不能把等待下降比例当作计算提速。

业务观察窗 3,985.693006 秒；原生 dispatch→末 token 平均并发 4.361448，
入口→终态上包络平均并发 7.631419、最大 8。3,932 个业务窗口资源采样中，
持卡 GPU utilization 均值 53.0375%，只是离散观测，不是连续 kernel 利用率。
1,745 个控制样本全部在窗口内，1,624 个有队列、其中 778 个低于 ready capacity；
这些样本不能直接证明哪一段是因果瓶颈，更不能仅凭利用率盲目提高并发上限。

规划回执 1,993 个全部完成；detach／排队／worker／接收均值分别为
47.342／395.715／478.750／235.409 ms，捕获至接收 1,185.988 ms。
这些阶段可能与生成重叠，不直接相加为用户延迟或 GPU 账单。

保留已通过语义资格的 D151 候选，其一次完整回放支持继续开发，但不作模型
验收。下一步结合已有日志、源码历史与原始实现资料，检验仍占用入口容量的
非生成工作与控制消息等待；一次只检验一个有证据的假设，不盲目重跑、放宽
超时或更改冻结指标。先完成 7B，再处理仍开放的 3B 历史差距；外部基线暂停。
旧 Prime 的新指标先审计可恢复字段，缺少数值身份、真实持卡或共同参考时不
从旧 CE 捏造，必要时只补匹配的旧／新 Prime 证据和公共标定。
