## 3. 对审稿问题的客观判定

**观察。** 修复后平均路由排队下降 58.65%，P95 TTFT 下降 64.88%；这只是
各一次开发运行的观测。使用两轮共同的 996 个有效请求，原队列均值为
294.555 秒、修复后为 121.871 秒，说明群体少一条请求不能解释此差异。
此匹配分析不删除完整失败记录、不构成统计显著性结论。

**解释。** 已联网重新核查固定官方提交：原始 `_load_balancer_loop` 每次把
候选集置空，然后无条件 sleep(1)，即使 ready 副本已经存在也一样。现有最小
修复只把 ready 检查提前；空集/满容量仍等待，RR 次序、scaler、加载策略未换。
原版 996 个可观察分配间隔中，无 <10ms 间隔；修复后为 410/995。
修复后中位数仍约 1 秒，不能据此声称修复无效，因为无可分配容量时的等待仍在。
[固定提交源码](https://raw.githubusercontent.com/ServerlessLLM/ServerlessLLM/9f50241baa5386e06a9321c51f19a9ef5f964c2b/sllm/routers/roundrobin_router.py)

**论文含义。** 审稿人要求解释“四分钟等待”成立；将它直接归因于 GPU 算力不足
或把它称为 ServerlessLLM 的模型启动时间均不成立。ServerlessLLM 原论文的贡献
包括快速分层 checkpoint 加载、迁移和启动感知放置，这些不等于此处的多租户
路由队列。应保留原版诊断，主比较采用合格的修复实现，显示名仍为 Serverless。
[原论文入口](https://www.usenix.org/conference/osdi24/presentation/fu)

**尚不能解释的部分。** 修复后仍有约 122 秒排队，不证明官方系统普遍如此。
target=2 同时限定每副本并发容量，诊断 max_num_seqs=4；需要在共同负载下
验证公开并发配置，而不能让对手固定在未经选择的诊断点。另有一个晚期连接断开
的原因未定，不能将其归因于轮询、OOM 或用户网络。首次三条请求失败与服务／
router 尚未建立有关，应修正入口生命周期，不能用推迟业务 t0 或隐藏重试消除。

## 4. 复用裁决与必须补齐的条件

| 项目 | 裁决 | 后续处理 |
|---|---|---|
| D72/D73 轮询原因对照 | 可复用，已复核 | 不再运行同一对照，不为 CI 补轮 |
| 原生 first/last-token 测量 | 有效代码与诊断可复用 | 新代码身份重新登记，不改为 payload/EOF proxy |
| 原生 checkpoint、已有环境、静态工件与 trace | 复用 | 不再转换 backbone、不复制整池、不造负载 |
| D72/D73 主性能和 GPU-s | 不能复用为新主结果 | R2；只有新合同受影响的资格和完整运行需要执行 |
| 实际远程交付 | 尚缺本路径证据 | 使用 D78/D80 已发布只读缓存，调用发生在服务资源域 |
| 请求到达早于 router ready | 存在真实失败 | 服务入口提前接收并保留排队，原始到达不平移，不增加隐藏 attempt |
| 全服务物理 GPU 生命周期 | 尚缺完整 lease 账本 | store 守护进程与所有 Ray/engine 持卡区间求并集 |
| 原生加载读回 | 早期资格及日志可复用 | D72/D73 在请求失败时提前跳过最终 worker 读回，下一轮必须在失败分支也取证 |
| 3B | 保留已完成 D74 证据 | 本阶段不重跑、不抢占 7B 主线 |

特别注意：现有专用原生 store 的历史资格显示其能持有四卡 context。
因此，backend 缩容不是物理 GPU 释放；不能沿用只数推理副本的旧成本计算。
具体新运行的持卡时长必须实测，不从旧 watchdog 秒级采样伪造精确 lease 边界。

远程适配前还必须区分原生 **registration-time 工件准备** 与请求时加载：
当前 controller 的 `skip_store_lora_registration=false` 会逐项调用
`register_lora_adapter`；历史本地工件因路径已存在而直接返回。
不能只把路径改为空目录就声称真实远程已启用，也不能偷偷把其准备策略替换
成 Prime 的按需 planner。应核查既有 native-vLLM 合法的 direct adapter 路径，
明确选择和披露准备模式，复用共同交付组件；两种模式的准备、传输和持卡均
纳入共同窗口。这里尚未改变策略或冻结新配置。
