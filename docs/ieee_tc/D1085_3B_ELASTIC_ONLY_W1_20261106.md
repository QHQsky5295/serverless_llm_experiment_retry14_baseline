# D1085：3B ElasticOnly W1 同版本 A1 更新登记

## 目的与唯一改变

D1085 更新既有 3B `ElasticOnly` W1 消融，使其与 D1082 Full W1、D1083 Full W0
和 D1084 Full W2 使用同一份当前 PrimeLoRA serving implementation。它不是
重新调参，也不是外部 baseline；唯一系统语义仍是 A1 已冻结的 ElasticOnly：
保留 autoscaling、vLLM backend、物理 allocation、请求驱动缓存和普通
load-only routing，关闭主动 adapter management、hierarchical residency、
handoff 和 effective-capacity admission。

D1085 的作用是为 D1082 Full W1 提供同版本机制对照，直接检验 elasticity-only
是否已经解释当前资源/尾延迟结果。若 Full 与 ElasticOnly 的差异不足或方向相反，
如实记录 trade-off；不通过改变 ElasticOnly 的定义、注入等待或削弱其缓存来
制造优势。D1057 的旧版本结果保持原身份，不被覆盖。

## 评价与收尾

D648 共同 TTFT/TPOT 合同、物理 allocation-union GPU-s、原生 token 和
`n_correct=null` 的 3B 结构限制均保持。运行失败、资源中止或机制未触发都
保留，不进入完整排名。完成后按既有 D1084 收尾路径：资源释放 → D648 重分析
→ profile/tier/delivery 审计 → 与 D1082 Full W1 的单轮描述性对照 → 白名单备份。

远端只启动已发布 3B gzip 服务；不打包、不重建工件、7B/k3s 不动。测量期间
不安装、构建、清理、压缩、修改远端或启动另一 GPU 任务。临时 NVMe/HOST
目录由 runner 绑定到本轮独占路径；完成后必须为空。
