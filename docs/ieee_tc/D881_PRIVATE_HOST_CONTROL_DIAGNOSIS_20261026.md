# D881：后台 HOST 准备候选的扩容反馈与后半段等待

2026-10-26。复用已封存 D870/D880 的完整 3B W2 记录，不增加 GPU 回放、
修改生产代码、重新生成数据、调整 SLO 或绘图。按 analyze-results 区分观测、
解释与下一问题；本次是有界候选分析，不是新的性能点。

资源下降 5.2253%，但联合少 12 条、P95 TTFT 增加 2.1932%；不能晋升为达标
Full。独立数值正确性继续未知，`N_correct=null`，无最终排名或运行间 CI。
这不是同后端纯微测：启用私有构造也需其匹配的 D879 初始化 profile；
不同闭环轨迹和单轮变异不能被抹去。

**决定：结束本次私有 CPU 构造候选的性能评价，不将它作为下一候选的默认
叠加基础。** 代码保留为 opt-in、全部成功/失败证据保留；原默认串行路径未
被覆盖。后续开发以 D870 的串行配置和匹配初始化为参照，不重跑 D870/D880
同键，也不为本次结果追加短 Full 或同类原生 profiling。没有改生产源。

## 2. 资源差的实际触发原因

复用 D730/D824 的逐事件核算：queue/upper、active/upper、TTFT/upper、
max-score、ready+pending、all-low 均与实际配置完全一致。

| 实际记录 | D870 | D880 |
|---|---:|---:|
| 控制采样数 | 1931 | 1930 |
| 两次扩容决策相对业务开始，s | 10.642 / 12.690 | 322.861 / 324.893 |
| 超过 1 的分量 | TTFT，1.369134 / 1.369134 | active，1.142857 / 1.142857 |
| 两次决策 TTFT 样本数 | 1 / 2 | 40 / 48 |
| 两次决策 queue 比值 | 0 / 0 | 0.125 / 0.25 |
| 两次决策 active 比值 | 0 / 0 | 1.142857 / 1.142857 |
| 首请求 TTFT，ms | 6845.669204 | 4329.559934 |
| 首请求 dispatch-window 等待，ms | 6304.861525 | 3700.095153 |
| all-low 次数 / 缩容次数 | 0 / 0 | 0 / 0 |

旧运行的首请求越过冻结的 5000ms 在线扩容线，新运行没有越过。D880 在后续
真实 active saturation 超线后扩容。在线阈值不是共同离线 SLO。两个新增
GPU 的物理分配边界延后合计 625.220878 GPU-s，释放边界反而增加 1.760052，
合计资源减少 623.460826；无中间释放间隙。这解释了控制动作和资源账目，
**不证明后台 CPU 构造使初始化更快，也不证明它直接节省了这些 GPU 时间。**

此反馈与 D824/D862/D867 已解释的机制相同，问题到此关闭；不改变阈值、
删去首请求、赠送额外准备时间，或再次启动同类控制诊断。

## 3. 后半段退化在哪里

phase 是共同输入按序每 500 请求的分析分组，不是 W2 的每 100 请求轮换。
下表差值为 D880−D870，完整八段全部保留；毫秒为段内请求均值之差。

| phase（从 1 计） | 联合达标，D870→D880 | TTFT 差 ms | 到达→准入差 ms | 准入→取得来源差 ms |
|---|---:|---:|---:|---:|
| 1 | 489→489 | -0.645 | -8.542 | -7.166 |
| 2 | 468→474 | -51.867 | -26.633 | -11.690 |
| 3 | 476→480 | -30.319 | -23.064 | +9.506 |
| 4 | 475→486 | -48.370 | -10.359 | -28.531 |
| 5 | 466→468 | +9.630 | +2.490 | +3.590 |
| 6 | 475→454 | +148.942 | +84.006 | +52.429 |
| 7 | 466→452 | +57.480 | +31.861 | +14.994 |
| 8 | 458→458 | +34.168 | +24.267 | +19.920 |

第 6/7 段净少 35 条，而前五段净多 23 条。第 6 段到达→准入增加 84.006ms，
其中 runtime-slot 包络增加 73.252ms；准入→取得来源增加 52.429ms，原生
prefill 只增加 1.144ms。第 7 段对应为 runtime-slot +29.425ms、来源
+14.994ms、prefill +0.465ms。runtime-slot 包络含确认/调度，不等于 GPU
确实无空位；它嵌套在到达→准入中，不能重复累计。

因此首阶段扩容差不能解释全部剩余服务违约；现有证据也不支持直接改 token
预算或将等待都归因于原生推理慢。第 6/7 段 GPU 来源请求反而分别增加 17/18
条，不能用命中数增加推导端到端获益。来源条件组不是共同因果对照。

## 4. 当前真实远端请求的准备分解

D880 有 510 条 selected-Remote，其中 503 条能关联其 own IO，7 条因共享
准备或来源变化不能冒领某次传输，全部仍在 4000 分母中。503 条中 133 条
TTFT 违约；D870 对应条件组为 505/123。两个组成员不完全相同，以下只描述
各自实际路径，不将条件均值相减当因果收益。

| 准入→来源取得的顺序阶段，均值 ms | D870，505 条 | D880，503 条 |
|---|---:|---:|
| 获取线程开始前 | 310.956 | 316.055 |
| 响应头 | 3.364 | 3.693 |
| 预留、接收与本地写入 | 237.941 | 260.175 |
| 解包开始前 | 0.108 | 0.091 |
| 解包与校验 | 77.992 | 80.904 |
| 文件发布包络 | 315.183 | 321.833 |
| 发布→原生加载开始 | 274.555 | 290.238 |
| 原生加载 | 39.369 | 41.026 |
| 合计 | 1259.468 | 1314.014 |

D880 顺序分解误差为 0ms；133 条违约条件组准备均值为 2250.903ms。
获取前、文件发布、发布后至原生加载三个本地包络合计约 928.125ms，占
该组全部准备均值约 70.63%。它们包含有用观察、等待、调度和验证，不是纯
锁时间或可全部删除的开销。接收含预留与本地写入，不冒称纯链路时间。

获取前的进一步分解复用 D833：movement 排队 77.940ms，attempt→pressure
建立 66.026ms，pressure start 包络 159.098ms；其中等待 RPC 回复累计
130.589ms 是嵌套项。全部 503 条精确 request/job/pressure/transfer 关联通过，
IO 后加入者为 0。不能据此重启已关闭的 D595/D598 并行 ACK、D822 压力共享、
D834 attach、D850 提前通知、whole-owner 线程、stat/projection/graph 方向。

本轮仍只有一个下一主线问题：**在保留原生状态新鲜性和容量语义的条件下，
准入与来源准备事务是否有可证明重复、却在前台付费的工作？** 先核对 D870
串行基础的实际调用链、D863/D868 已有 CPU 证据和历次否决原因，再查对应
官方实现；没有具体新前提不启动新候选或 GPU 诊断。D869 已合并的 registered/
staged 清点不重复实现，不以缓存过期状态替代确认。下一轮必须给出具体可
证伪的依赖变化或排除结论，不能继续泛化为“再分析整个系统”。

## 5. 资源、来源、保护与剩余范围

分析复用 D730 控制核算及未改的 D703 preparation/prefetch analyzer，源 SHA
与封存 D870/D880 一致。程序、执行块、两个完整控制汇总、4000 请求八段表、
503 个精确请求关联和原始出处保存在
`paper_results/ieee_tc/p2_backend/d881_private_host_control_diagnosis/`。
第一次 CPU 入口仅设 cgroup AllowedCPUs 未设进程 affinity，在读取结果前
被原有检查拒绝；第二入口增加既有 taskset，分析完成。不是性能重跑，未
放宽资源检查，两次入口事实保留。

分析域峰值 764837888B，high/max/OOM/swap 均 0，域已退出。无 GPU、远端
或共享 k3s 操作。当前磁盘约 162GiB 可用；新数据约数百 KiB，不复制权重或
大原始文件。147 项历史保护与用户 manifest 由 closure 核验，备份由独立
回执确认，不预先声称最终 V2 已同步。
