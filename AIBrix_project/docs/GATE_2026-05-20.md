## Formal Blocker

The full AIBrix system needs Kubernetes resources, not only a local sidecar:

- AIBrix CRDs and controller-manager;
- Envoy gateway and gateway-plugins;
- GPU vLLM pods labelled for AIBrix routing and adapter scheduling;
- runtime sidecar in each model pod;
- `ModelAdapter` CRDs for LoRA loading.

Current machine state blocks that path:

- `/usr/local/bin/kubectl` and `/usr/local/bin/helm` are executable only by
  root;
- Docker client exists, but `qhq` cannot access `/var/run/docker.sock`;
- `kind` and `minikube` are absent;
- passwordless sudo is unavailable.

This is a platform/runtime blocker, not an adapter-path blocker. The runtime
LoRA component gate proves local LoRA API compatibility, but a formal same-trace
`e2e_v3` run would require a GPU Kubernetes deployment that preserves AIBrix's
control plane.
