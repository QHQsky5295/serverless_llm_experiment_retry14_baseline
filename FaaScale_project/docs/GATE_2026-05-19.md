## Runtime Gate

The runtime gate then fails for the actual RDMA device path:

```text
found 0 device(s)
before_init
searching for IB devices in host
verbs_initialize() - ERROR!!!!!!!!!!!!!!
after_init False
```

Current machine state:

- `/dev/infiniband`: absent.
- `/sys/class/infiniband`: present as a sysfs class path but no usable IB
  device is exposed to userspace.
- `/dev/gdrdrv`: absent.
- passwordless `sudo`: unavailable.

This is a runtime hardware/driver-exposure blocker, not merely a source path
or Python dependency issue.

## Decision

FaaScale/LambdaScale is closed as a build/import/local-adapt gate, not a formal
comparison row, on the current machine.

Do not add it to the main comparison table or figures unless all of the
following become true:

- the RDMA device stack is visible to userspace and `wrapper_initialize`
  succeeds under the same isolated env;
- a Llama-3.2 3B model path/config is added without changing the closed
  workload variables;
- a LoRA/adapter workload path is implemented or a clearly documented
  non-LoRA appendix workload is approved;
- metrics can be emitted into the existing `e2e_v3` schema under the same
  true-remote trace, adapter subset, and artifact endpoint policy.
